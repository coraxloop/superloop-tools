# Steward client

`superloop-steward send SERVER [--session ID] MESSAGE...` resumes the selected server conversation and streams its reply. Without a session, discovery selects the newest primary session from the exporter's list, excluding nested subagent transcripts. The remote argument contract remains `claude --resume ID --print -- MESSAGE`. Sending changes remote conversation state and can cause the steward to act; transcript inspection does not send a message.

`superloop-steward transcript poll SERVER` and `transcript watch SERVER` read complete JSONL records through the existing exporter list/read protocol. All commands require a provisioned absolute `--known-hosts FILE` and accept `--ssh-config FILE`; the selected alias is `SERVER-steward`. Unknown keys refuse without enrollment, updates, ambient global key sources or connection sockets. Configured proxy transport remains an external dependency. `--exporter PROGRAM` names the server's transcript exporter. It defaults to `/usr/local/libexec/superloop/transcript-export`, the server kit's private path under the documented `/usr/local` prefix; a server whose kit is installed under another prefix, or that has not yet been handed over, is named with `--exporter` and its own exporter command.

The default state remains `~/dev/superloop-tools/steward-transcript-watch`, configurable by `--state-dir`. Shared `cursor-SERVER` files retain their V1 canary and tab-separated path, device/inode, acknowledged offset, high-water, observed size, `mtime:ctime` (each in integer Unix epoch seconds since `1970-01-01T00:00:00Z`), tail start and SHA-256 columns. Bare reads preserve cursor bytes and metadata, create no scratch state and refuse when access-time preservation is unavailable. The protocol still reports replacements, truncation, regression and rewrites, and includes nested transcripts. Only unprotected file-history-snapshot plumbing is filtered, with an explicit count.

`--advance-cursor` serializes changing callers with a per-server descriptor-held `flock` lock and saves only after output is flushed. It stages and synchronizes a changed cursor before an atomic rename. The kernel releases the lock when its holder exits or is killed. The stable lock file remains as bookkeeping and must not be unlinked. Existing empty cursor files refuse by name; only absence starts an initial reading. A failed output cannot acknowledge records; a failed save after output may cause replay. Watch calls the polling module and publishes any summary needed to acknowledge filtered records or changed observations; empty unchanged polls stay quiet until expiry, which prints a duration line and exits 2. A transport failure after the watch deadline also exits 2 without publishing or acknowledging an incomplete batch; failures before the deadline remain loud. Existing transcript deadline, read-size, tail-size and watch timing environment variables retain their names. Send reports its wall on stderr so reply bytes on stdout remain unchanged.

External process dependencies are SSH and timeout, the configured exporter and the send command's Claude program. Exporter list operations retain their existing remote temporary census files; operating-system authentication logs and read access times are not client cursor writes. Fixtures replace every remote operation with isolated protocol data. The manifest is the sole version authority for the tier 2 steward release group; bite 4 ingests and replaces its interim metadata, release checker and pending-retirement inventory. No old-name alias or shim installs.

Pass `--known-hosts "$HOME/.ssh/known_hosts.clients"` from inside the loop entry after its provisioning row in the runbook has been applied. This pinned public-key file is never created or updated by the client.

A sole `--version` returns one JSON control-plane record on stderr with the installed name and manifest version, no stdout bytes, and exit status zero. The shared release checker verifies this form.

The transcript exporter belongs to the steward server release group. The client invokes it through the configured SSH exporter command; no workstation copy is installed. Its source and configured build output remain available for the server kit handover.

Meson installs the client into the configured binary directory and its identity-bearing build record into the data directory. The predecessor programs and the former client provenance sibling retire through reviewed home-prefix inventories after callers have switched to this client.
