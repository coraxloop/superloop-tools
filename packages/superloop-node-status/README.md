# Node status

`NODES="alpha beta" superloop-node-status LOOP --known-hosts FILE` reads each configured `NODE-LOOP` alias and reports core counts, one-, five- and fifteen-minute load, one-minute load per core and the lighter node. The first minimum three-decimal ratio wins a tie. `NODE-STATUS-DURATION-MS` reports elapsed wall on success and failure. Unreachable or malformed readings are reported; no valid reading is failure. `NODE-STATUS-FAILED` names the configuration, transport or load stage and its input: the resolved alias and configuration path, known-hosts file, SSH exit and last stderr line, or unparsed load output. Successful peers remain eligible when another peer fails.

`--ssh-config FILE` selects the configuration, defaulting to the user's `.ssh/config`. `--known-hosts` is a required absolute provisioned host-key source. Unknown keys refuse, and SSH cannot enroll keys, update trust or create persistent connection sockets. Configured proxies remain operator-controlled transport dependencies. Node selection reads NODES supplied from the instance registry, never a compiled estate list. `NODE_STATUS_TIMEOUT_MS` bounds each read, defaulting to eight seconds.

The client runs SSH and timeout from PATH; its remote command only reads nproc and proc load averages. Timeout statuses 124 and 137 report `deadline_ms=N expired`, and statuses 125 through 127 report `wrapper_exit=CODE`; these do not claim a measured SSH exit. Other unsuccessful exits report numeric `ssh_exit=CODE`, or `ssh_signal=N` for signal termination. It writes no cursor, node state or local state. Authentication audit records remain operating-system bookkeeping. Its package is tier 2 with independent release group `node-status`; the manifest owns its version. Bite 4 ingests and replaces its interim metadata, version checker and pending-retirement declaration. The former executable is not installed as an alias or shim.

Inside the loop entry, pass `--known-hosts "$HOME/.ssh/known_hosts.clients"` after the runbook's client host-key provisioning row has been applied. This file contains independently verified public node keys; node status never creates or updates it.

A sole `--version` returns one JSON control-plane record on stderr with the installed name and manifest version, no stdout bytes, and exit status zero. The shared release checker verifies this form.

Meson installs the client into the configured binary directory and its identity-bearing build record into the data directory. The predecessor programs and the former client provenance sibling retire through reviewed home-prefix inventories after callers have switched to this client.

## Daily storage observations · `sec:nodestatus:daily-storage-observations`

**Protocol (Storage sample record)** · `proto:nodestatus:storage-sample-record` `superloop-node-status storage sample --config FILE --state-dir DIR` keeps one schema-one JSON sample per UTC date. The root-owned configuration must be a regular file writable by neither group nor other; the sampler opens it without following a link and refuses `configuration-custody` before a reservation if custody fails. It names `node_id`, `incarnation_id`, `configuration_revision`, `reader_gid`, volumes and account/storage-class rows. Each volume names an ID, `mount_path`, `query_path`, expected `major_minor`, `filesystem_type` and `source`, and `capacity_scope` (`filesystem` or `project_scoped`). The sampler opens the query directory once without following a link, selects the last, topmost mount-table entry at the configured mount point, and compares that entry and the opened descriptor's device with the configured identity. It then reads `FS_XFLAG_PROJINHERIT` with `FS_IOC_FSGETXATTR` and `fstatvfs` counters through that descriptor. An inherited project is `project_scoped_query` even when configuration says `filesystem`; a configured `project_scoped` query remains unmeasured even if the flag is clear. If the attribute query cannot answer, the status is `failed` with `project_attribute_unavailable`, not an assumed plain filesystem. `fstatvfs` fragment size times block counts gives integer `total_bytes`, `free_bytes` and `available_bytes`, with total, free and available inode counts. A project-scoped query is deliberately `unmeasured`: a project limit reported by the kernel is not a filesystem capacity. A missing mount, wrong identity, failed query or invalid counter produces a typed error and null numbers, never zero. This is a kernel counter reading, not a file walk or quota query.

The sample has `schema=1`, `node_id`, `incarnation_id`, `state_nonce`, `sequence`, `scheduled_date`, `configuration_revision`, `status` (`complete`, `partial` or `failed`), `errors`, `volumes` and `accounts`. `state_nonce` is the UUID made once for this state directory; it changes if the directory is replaced even when node and incarnation IDs stay the same. Sequences start at one and increase by one per durable date reservation. The date is UTC `YYYY-MM-DD`; sequence, counts, UID, project ID and nanosecond fields are unsigned JSON integers, with count and nanosecond values bounded by `u64` and UID/project IDs by `u32`. The top level, each volume and each account row carry an `interval` with `started_utc_ns`, `finished_utc_ns`, `boot_id` and monotonic `elapsed_ns`. An identity is `{major_minor, filesystem_type, source}`; `observed_identity` is null if it could not be read. An error entry is `{volume_id, kind}`. Volume status is exactly `complete`, `unmeasured` or `failed`; error kind is exactly `mount_absent`, `identity_read_failed`, `identity_mismatch`, `project_scoped_query`, `project_attribute_unavailable`, `counter_read_failed` or `counter_invalid`. A complete volume has no error and non-null byte and inode counters from one verified descriptor; other statuses have null counters and an error. An account row retains `account_id`, UID, storage class, volume ID, nullable project ID, `collection_enabled`, `coverage=unmarked`, `status=not_measured`, and nullable charged bytes, charged inodes and limits. No account number is inferred from a volume counter. A failed volume can coexist with successful volumes; all failed volumes give a failed sample. The record form admits later project readings without changing its envelope.

An exclusive nonblocking sample lock covers the reservation, kernel reads and publication. The sampler publishes `state-nonce` durably on first use; it refuses a missing nonce beside existing attempts or samples. Before any kernel query it durably reserves the date and next sequence in `attempts/DATE.json`, whose whole public shape is `{sequence, scheduled_date}`; a stopped attempt leaves that file without a sample and cannot be retried for the date. A clock moving backwards cannot select an earlier date; a later UTC date needs no extra 24-hour gap. A closed sample is published to `samples/SEQUENCE.json` by no-replace rename after file sync, then directory sync. Published samples are immutable and never pruned by this command. The state directory is owned by the sampler and its configured reader group; the state, attempts and samples directories are mode 0750 and the nonce, sample and attempt files 0640. Provisioning grants only the administrator's export account membership of that group. A full record directory leaves the reserved attempt unfinished and `STORAGE-FAILED` on stderr; the next date may still run. The unit's journal also retains that failure. No failed read is printed as zero.

**Protocol (Storage export)** · `proto:nodestatus:storage-export` `superloop-node-status storage export --state-dir DIR --after-sequence N --limit M` reads kept samples and reservations; it never samples. `N` is an unsigned sequence, default zero. Its one-line JSON page has `schema=1`, `state_nonce`, `after_sequence`, `next_after_sequence`, `has_more`, `samples` and `unfinished_attempts`. Both row arrays are in ascending sequence order; an unfinished entry is exactly `{sequence, scheduled_date}`. `M` is 1 through 16, default 16, and bounds their combined row count; the serialized page is at most 1 MiB, each sample at most 256 KiB and each attempt at most 1024 bytes. A page can contain fewer than `M` rows to keep that byte bound. The caller pairs its cursor with `state_nonce`; a changed nonce means the archive was replaced and the cursor must be reset and reconciled. Advancing to `next_after_sequence` consumes the reported rows, so a caller retains each unfinished sequence and revisits it by exporting from the sequence before it. Its sample can still be published while its reservation is the latest, because the sampler holds its lock from a reservation through that sample's publication; once a later sequence appears in either array, the earlier unfinished attempt is final. A sequence beyond the end returns both arrays empty, `has_more=false`, the same cursor and the current nonce. Export failure writes `STORAGE-FAILED` on stderr, no JSON page and status 1. Export only requires read and traverse access to the root-owned sample archive through its configured reader group.

**Setup (Storage sampling unit)** · `setup:nodestatus:storage-sampling-unit` The package ships `superloop-node-storage.service.in` and `superloop-node-storage.timer.in` under its data directory. Provisioning renders the binary and configuration paths, writes the root-owned reviewed configuration, and separately activates the system unit; installation alone activates nothing. The rendered service reads `SYSCONFDIR/superloop/node-storage.json` and keeps its state in `/var/lib/superloop-node-status/storage`. Its `StateDirectory=superloop-node-status` with mode 0755 provisions the traversable parent; the sampler creates its `storage` child at 0750 for the configured reader group. The root oneshot is scheduled at 03:00 UTC with `Persistent=true`, no automatic restart and a ten-minute start timeout. The sampler's nonblocking lock prevents an overlapping kernel reading if a filesystem wait remains uninterruptible after that timeout. A missed date is not recreated, and neither a timer nor export makes a second attempt on a reserved date. The load-reading command's output is unchanged; a missing `--known-hosts` or loop now fails with `NODE-STATUS-FAILED` and status 1 instead of as a usage error.
