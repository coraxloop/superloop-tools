# `build-sync` · `guide:buildsync:build-sync`

`build-sync` turns one release-profile Cargo binary into a declared build output while preserving the output's modification time when its bytes already match. Meson builds the workspace once and uses this primitive to stage each binary (`[TOOLS-dec:mesonlayer:cargo-sync]`).

## Commands · `sec:buildsync:commands`

```text
build-sync [--artifact EXECUTABLE] --ledger PATH --source-root PATH --source-repository NAME --source-commit COMMIT [--domain NAME] <cargo> <manifest> <package> <bin> <output>
build-sync --probe <stamp>
build-sync --ledger PATH --source-root PATH --source-repository NAME --source-commit COMMIT --record <output> --producer <program> [--domain NAME]
build-sync census --root <source-root> --report <report> [--ledger <configured-ledger>] [--cargo <cargo>] [--installations-only]
```

The sync runs a package-scoped, locked Cargo release build and selects the `compiler-artifact` JSON message whose target name is `<bin>` and whose `executable` is set. Cargo's stderr passes through; the primitive writes no stdout on success. A failed build or missing matching artifact leaves the output and its build record untouched.

Artifact mode stages an existing executable without running a Cargo build, retaining the same byte comparison, executable mode and build-record contract. Its `build_wall_ms` measures staging through the output digest, including version queries and publication, rather than attributing a per-binary compile wall to a shared build. Meson's workspace producer records the aggregate compilation wall, source commit and resolved artifact features in `workspace-build.json`; the per-binary staging records do not attribute that shared compilation to every binary. The producer declares each executable output and writes file and directory dependencies so source changes, added inputs and removed artifacts invalidate the build while an unchanged staging graph invokes no Cargo command.

The dependency file does not track compiler identity or Cargo environment variables. After updating the toolchain or changing variables such as `RUSTFLAGS`, recreate the Meson build directory before staging; the gate already uses a fresh checkout and build directory for every run.

The domain defaults to `unset` until the graph configures one. `--probe` succeeds silently only for an empty regular file; every other path returns status 1.

## Dependency census · `sec:buildsync:dependency-census`

The dependency census reads Cargo's locked metadata and the dependency rows emitted by Meson. A synced helper finds the configured ledger above its executable; a Cargo debug binary requires `--ledger`. The release suite runs `release-dependency-census` against the configured ledger. Reconfiguration is required after a declaration changes: a configured ledger that differs from its source rows refuses before Cargo runs.

The separate Meson file census, run by `superloop-lint census`, refuses untracked generated files under an in-tree `BUILD/` as `untracked_path`: `Finding::UntrackedPath { path }` becomes `code: "untracked_path"` in `packages/superloop-lint/src/meson_census.rs`. Generated files under `BUILD/` are not tracked source files, and the ignore rows of `.linter/shape.toml` carry no `BUILD/` exclusion. A lane's Meson build directory must live outside the checkout and its `.git`, under or beside the lane's temporary root; name both paths explicitly in the brief, for example `$TMPDIR/build-N` under the temporary root, or sibling `lane-N-meson` and `lane-N-tmp` directories. Moving generated files beneath `.git` is not the lane build layout.

The report contains package tiers, explicit versions and release groups, normal and development edges, resolved external closure roots and checksums, installed-name program versions, executable call sites, interpreter payload identities, native and migration-map destinations, shared-file contracts, source imports and pending successor rows. Cross-package Rust file inclusion participates in the downward rule even when Cargo has no corresponding edge. Payload declarations bind an owner, interpreter, execution host and source digest. Native destinations resolve the build's configured installation directories; migration maps remain measured inputs until their retirements.

The call inventory scans production and test Rust sources for process constructors, imported constructor aliases and native execution functions. Transported commands have separate declarations with their execution host and source anchor. Script, Python and unit declarations include reviewed outgoing calls and bind the complete source digest, including embedded fixture programs. Meson executable forms are tokenized independently of the ledger; their argument tokens are checked against the reviewed declaration, including forms inside loops. Strings and comments do not manufacture executable forms. Shared-file rows name their writer, readers, format authority and source anchors. These source checks preserve the review boundary; they do not infer arbitrary program behavior from variable names.

Missing, duplicate and stale declarations are findings. The report is retained on a census refusal so the unresolved identities remain inspectable. A refusal before measurement completes retains a schema-one document with `complete: false` and the original diagnostic in `error`; it is not a measured graph. An unwritable report path is reported alongside the original refusal. The final census admits no tier debt. Source imports receive no test exemption. Registered test tools join Cargo-provided binary targets or the actual configured Meson suite environment. The superloop-pack fixtures receive the built linter through `PUBLIC_PACK_TEST_LINTER`; request fixtures receive the built private helper through `SUPERLOOP_TEST_REQUESTS_HELPER`. Missing bindings refuse by name, and neither fixture builds another package to discover its executable.

**Rule (Document installation coverage)** · `rule:buildsync:docs-prose-installed` Exactly one `installation-inputs` ledger row names its nonempty `owner`, a `maps` array of normalized repository-relative file paths and a `document_roots` array of normalized repository-relative directory paths without trailing separators. Duplicate or escaping paths refuse. Map files are explicit inputs and must resolve within the source root; map targets still require matching installation ledger rows. Every Markdown document beneath a declared document root in the configured build's `declared-paths.txt` must have a declared copy target whose source and destination equal its repository-relative path, or, when included by the public manifest, a native installation. Missing coverage reports `docs-prose-uninstalled`. An absent or malformed evaluated list reports `docs-prose-unreadable`. An empty map array selects native installation only; no directory is scanned implicitly.

Documents-only repositories use `census --installations-only` with the same configured ledger and Meson introspection. This mode compares that ledger with the root Meson declaration and checks installation inputs, destinations and document coverage without reading Cargo metadata or package contracts. Its report identifies `scope` as `installations`; it is not a dependency-graph verdict. An instance can declare `deploy/tools/maps/share-map.toml` in `maps` and `docs/tools` in `document_roots` without changing the source root.

## Output and record · `sec:buildsync:output-and-record`

**Rule (Package accountability)** · `rule:buildsync:package-accountability` Each dependency-census packages row includes `accountable_owner` and `consumers`. Exactly one `accountable-owner` ledger declaration names each measured package and its uppercase accountable domain owner; missing, malformed, duplicate and stale declarations refuse the census. A package that record 036's domains table (`[TOOLS-tab:toolsdeps:session-request-domains]`) lists must declare the owner that table names, because the owner is stated in both places: a disagreement refuses as `accountable owner disagrees with record 036`, an absent domains table or a malformed row refuses the census, a table row naming a package outside the workspace refuses as `record 036 domains table names a package the roster lacks: {package}`, and a package the table does not list is admitted on its declaration. Package membership is checked against the workspace before owner validation, so an unaccounted package omitted from the ledger retains its specific finding alongside independent owner findings. This accountability is distinct from the linter's mechanically derived corpus owner. The `accountable_owner` field reports that declaration and is never inferred from the graph. The `consumers` field is a sorted unique array of source package names derived from all measured internal Cargo edges, including normal, development, build and target-specific edges; an unused library reports an empty array. It describes the measured graph, not planned future consumers.

Different bytes are staged in the output directory, flushed, set to mode 0755, and renamed over the output. Equal bytes with a wrong mode receive an in-place mode repair that keeps the modification time. Equal bytes at the right mode cause no write.

The compact, key-sorted `<output>.build.json` object carries `bin`, `build_wall_ms`, `cargo_version`, `domain`, `installed_name`, `package`, `profile`, `release_group`, `repository`, `rustc_version`, `sha256`, `source_commit`, `version`, and `written`. The configured ledger resolves the output's unique installed identity and owning manifest or shell release group. A repository identity and full source commit are required; an unregistered output refuses before publication. The version commands are `<cargo> --version` and the `RUSTC` executable, or `rustc` on `PATH`, with `--version`; `cargo rustc --version` is not a supported Cargo invocation. A changed source identity rewrites the record even if executable bytes match. Equal bytes and identity preserve the record. `written` is UTC RFC 3339.

Record mode reads a regular output already written by another program and leaves it untouched. Its record uses the output file name as `bin`, the ledger owner as `package`, `generated` as `profile`, the supplied domain or `unset`, the output digest as `sha256`, and its own elapsed time and UTC timestamp as `build_wall_ms` and `written`. The first stdout line of `<program> --version`, or the `fields.version` value of a superloop-cli-common version record on stderr, fills both `cargo_version` and `rustc_version` because the producer is the toolchain for a generated output. A matching output digest, source identity and producer version leave the record's bytes and modification time unchanged. Native program rules install the corresponding record beneath the data directory's `superloop/build-records` directory.
