# Claude hook adapter · `guide:superloopclaudehook:claude-hook-adapter`

The private tier 3 adapter accepts exactly `stop`, `pre-tool-use`, `session-start` and `user-prompt-submit`. Before reading session state, invoking an entry or running the permission helper, each command requires its corresponding Claude `hook_event_name`. Malformed and mismatched payloads refuse visibly. Heartbeat and rulebook decisions and persistence use the same tier 1 `session-core` as the retained compatibility binaries. The adapter contains Claude decoding and reply rendering, without linking either compatibility tool or the permission package.

An isolated heartbeat, rulebook or letters response retains its exact bytes. When both contexts are present, the combined response contains the rulebook context, two newline bytes, then the letters context in one `hookSpecificOutput.additionalContext` string. The event field precedes the context field, with compact JSON and no trailing newline. The built-binary contract fixture pins this combined response for `SessionStart` and `UserPromptSubmit`.

`PreToolUse` always evaluates both heartbeat authorization and permission triage. Infrastructure refusal wins first, then heartbeat exit-two refusal, then a structured permission denial at exit zero; a warning, audit silence or allow cannot erase any denial. When triage allows beside a heartbeat warning, the adapter publishes exit zero so the harness applies the allow, and carries the warning in the reply's `systemMessage` field and on standard error. With audit silence alone, the warning retains exit one. The helper is an exact absolute `PERMISSION_TRIAGE_HOOK_BIN` configured at compile time by Meson; runtime environment values cannot redirect it. The default development location is the home private hooks directory. The adapter validates the instance grammar and regular executable ELF helper before invocation, clears inherited instance variables, and passes the original payload bytes. A compile-time `PERMISSION_TRIAGE_INSTANCE` selects an absolute instance path; otherwise the retained home instance is used. Runtime instance overrides are ignored.

Unreadable or oversized input and caught panics refuse at exit two for `pre-tool-use`. For `stop`, `session-start` and `user-prompt-submit`, these faults fail open with empty output at exit zero, recording a redacted payload or panic fault through the retained logging functions. Event-name mismatches still refuse before effects. The adapter runs the retained rulebook oracle tests and the heartbeat specification fixtures through its built binary, including argument dispatch, so decoding drift is checked alongside the isolated and combined response contracts.

Meson installs the adapter beside the separate permission helper in `libexec/superloop/hooks`. Installation does not register a hook. Old wrappers, binaries and toggles remain effective until complete registration and session-drain proof; public toggle consolidation and removal of the heartbeat alias wait for bite 11. The shared command/version convention waits for bite 4. The release suite tests the current version record for this binary.

The `harness-private` install tag selects this adapter, the permission hook and `requests-helper` for isolated staging. Use `meson install --no-rebuild --only-changed --tags harness-private --destdir STAGE` after building those outputs; repeating it preserves installed bytes and metadata. It writes no harness registration. The worker generator emits the configured adapter path followed by `pre-tool-use` in newly generated settings; existing worker homes and every host registration stay unchanged until the superloop's migration step. The worker instance file and the separately installed permission helper remain required, with missing configuration refusing visibly.

Migration reads every effective host and worker settings source before establishing the switch point, then accounts for all sessions and resumable worker homes that could retain an old path. Unknown sources or users keep the old executables installed. New-name events, old-user exit or restart evidence and a final serialized source read-back are prerequisites to retirement. The retained permission assembly fragment still describes the compatibility registration; it is not the new adapter registration or evidence that migration occurred.
