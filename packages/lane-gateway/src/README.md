## Serve liveness implementation · `sec:lanegateway:serve-liveness-implementation`

`serve.rs` owns the dedicated heartbeat publisher, typed shared activity snapshot, atomic fixed-state writer, private `serve_inner` loop, and unwind-catching supervision seam. The publisher writes once before registration reconciliation and independently at the configured cadence, so synchronous runner waits do not starve liveness publication. Main-loop updates change last activity only for request start, result publication, and open-proposal reconciliation; cadence-only writes change heartbeat time alone.

The request channel is read through one classifier that separates an absent file, a prefix, and a whole document: emptiness, a truncated trailing UTF-8 sequence, and a JSON parse ending at end of input are prefixes, and every other decoding or parse failure is a document refused on its merits. Per-lane cycle state travels with the seen-request map, so a waiting episode counts its own cycles, appends its audit record once, and is forgotten when the file completes or disappears. The seen-request check runs before the waiting counter, which is what keeps a permanently truncated file from opening a fresh episode after its refusal.

The supervision seam always stops and joins an initialized publisher, and marks the shared snapshot stopped with its typed reason before the final publication, so every exit the process can observe about itself reaches the file. A clean inner return publishes stopped `clean_shutdown` for the operator's flag and stopped `signal_stop` for a delivered signal, with the flag or the accepted signal as its reason; a returned `GatewayError`, caught panic, publisher failure, or join failure publishes stopped `error` or `panic`, remains nonzero, and attempts the strict fixed crash report. Marking is best effort against a poisoned snapshot lock because the failure paths already report themselves and a heartbeat left saying `running` is exactly what the published pid and cadence exist to settle. Only the accepting thread installs once per process behind a `OnceLock`; the block itself is repeated on every entry to `serve`, because a signal mask is per-thread and a generation entered from a second thread of a process that has already served would otherwise run unblocked. The accepted-signal record is reset at that same point, so a test binary that serves many times starts each generation having observed nothing. Atomic heartbeat and crash writes use synced create-new sibling files and remove unpublished temporaries after a write or rename failure. Gateway path helpers keep both artifacts directly below the state root, and exported health/crash types let the binary and process tests inspect their strict schema-one shapes without exposing the private loop seam as public package API.
