# Credential observations · `guide:credentialcustody:observations`

`superloop-credential-custody` observes completed sealed-file metadata, compares calibration identities and owns bounded fixture campaigns. It is a tier-2 Rust package in release group `credential-custody`. Authority is per command, as listed below; the executable never gains privilege itself. Meson installs the binary and its build record with the other public commands, and nothing invokes it; a rehearsal's root-owned copy is a separate operator installation.

## Commands · `sec:credentialcustody:commands`

```text
superloop-credential-custody length-observe --parameters FILE --case NAME --receipt NAME
superloop-credential-custody format-discover --parameters FILE --case NAME --receipt NAME
superloop-credential-custody identity-check --parameters FILE --calibration FILE --receipt NAME
superloop-credential-custody calibration-run --parameters FILE --campaign CAMPAIGN
superloop-credential-custody descriptors --parameters FILE --case CHILD
superloop-credential-custody barrier-release --parameters FILE --case CHILD
superloop-credential-custody completion --parameters FILE --case CHILD
```

The parameter record is reviewed metadata, not an untrusted command service. It must be a regular, single-link, effective-user-owned file with mode exactly 0400; `parameter-custody` refuses a violation before any probe runs. Probe argument vectors are explicit operator authority to execute their named programs; no shell expansion occurs. The caller must exclude deployment and file replacement throughout observation. Sealed inputs must be completed, regular, single-link, caller-owned and mode 0400, beneath the declared sealed root. The sealed root and each NAME directory must be effective-user-owned, mode exactly 0700, with a nonzero directory link count (`sealed-directory-custody`). Directory link counts are filesystem-dependent and include subdirectories, so they are not required to equal one or two. The parameter and sealed-directory walks from `/` follow no symlink (`path-open`); each ancestor must be root- or effective-user-owned and not group/other-writable unless sticky (`directory-ancestor-custody`). Sticky trusted ancestors preserve the ownership protection of their children. These checks prevent another account from replacing a directory or sealed entry between the observer and payload reads. They do not exclude concurrent writes by the effective user; the caller still excludes those. Configure resolved paths from `/`, including a resolved local-installation prefix when the advertised prefix is a symlink. Completion assertions bind each file digest to its case and invocation. An invocation can cover paired names but cannot identify different input lengths or content cases. These observation commands consume those assertions. The separate launcher retains process-completion evidence; a future observation-record version must bind that evidence before these observations can witness a real campaign.

## Authority and operator preconditions · `sec:credentialcustody:authority`

|Command|Required authority|Writes|
|-------|------------------|------|
|`format-discover`|Ordinary effective user owning its record/input and evidence directory; root may use root-owned inputs after the checks below|One metadata receipt|
|`length-observe`|Same ownership; read access to the reviewed payload, source repository and identity files; permission to execute reviewed metadata probes|One calibration receipt|
|`identity-check`|Same ownership; immutable calibration and reviewed metadata probes|One comparison receipt|
|`calibration-run`|Host uid 0, observed bounding/permitted/effective sets exactly `SYS_PTRACE` and `KILL`, empty inheritable/ambient sets, no-new-privileges; intentional manager access under the operator's loaded unit witness|One resident pair, immutable child evidence and bounded campaign matrix|
|`descriptors`|Host uid 0, exact `SYS_PTRACE` sets, empty inheritable/ambient sets and no-new-privileges; both manager sockets inaccessible in the installed unit|Requests keeper inventory and receives an observation-only pidfd; keeper writes the receipt|
|`barrier-release`|Host uid 0, all capability sets empty and no-new-privileges; both manager sockets inaccessible|Requests the keeper's retained-inventory transition; no independent signal|
|`completion`|Host uid 0, all capability sets empty and no-new-privileges; both manager sockets inaccessible|Reads the live keeper's retained completion; no holder stop or independent completion publication|
|`credential-fixture emit`|Effective uid must be nonzero; reads a caller-owned 0400 or root-owned 0444 public case record and receives two writable named pipes|Synthetic streams and metadata stdout; no receipt or other filesystem write|

Before a root run, the operator reviews the exact probe vectors and every input they interpret, selects an independently reviewed tagged build, and records installed version identities, artifact/payload digests, owner/mode/link metadata and resolved paths. Freeze installation changes for the whole observation. Verify all dynamic-loader libraries, interpreter modules and configuration lookup paths are root-owned and not writable by another account; retain the actual loaded-library mappings and package/image identity as the witness. An executable descriptor pins the program inode, not its dynamic loader or libraries. The observation commands do not establish those dependencies' provenance; their campaign handoff remeasures protected artifact and policy bytes and retains the completed producer's measured configuration binding.

Each executed program is walked under the protected ancestor rule, must be a regular root- or effective-user-owned executable (one link for effective-user ownership; nonzero links for root-owned packaged files) with no group/other write or special mode bits, and runs through the existing `loop-home` checked-descriptor executor with no pathname fallback. Its checked device/inode must equal the retained execution identity. Executable scripts with close-on-exec interpreter requirements refuse; use reviewed native programs or explicit reviewed interpreter vectors. Only the fixed `/usr/bin/python3` entry permits vendor symlink resolution after its parent is protected; the resolved file is then checked and pinned. Host pinning additionally admits writable sticky ancestors only when root-owned, and requires the host's own initial user-namespace map. Do not enable a remapped user namespace, including a manager's `PrivateUsers=`, for observers or the fixture re-exec case. The reused ``packages/loop-home/src/anchor.rs`` and ``packages/loop-home/src/ancestor.rs`` now execute within a program intended for root use; a change to either is a custody change requiring custody review. Evidence-root and calibration walks enforce the same ancestor rule as parameter reads.

Runtime Git extraction is retained for this cut: it directly verifies the exact committed parser body against the installed bytes, without changing that body or fetching anything. The repository root and its ancestors are checked and retained, but this does not freeze its recursive contents. Before a root run, inspect and retain recursive ownership/write-permission results for the repository, its Git directory, configuration, object stores and any alternates; require root control throughout, review configuration and external lookup paths, and exclude concurrent repository modification. Git itself is checked and executed by descriptor, with `-c protocol.allow=never` and a fixed empty `GIT_ALLOW_PROTOCOL` allowlist overriding repository per-protocol settings, so a missing object cannot start a fetch transport. Immediately before every root run, retain a recursive owner/mode listing of the repository, Git directory, config, objects including alternates, and refs; require root ownership without group/other writes, review `git config --list --show-origin`, and keep the repository unmodifiable for the observation. Moving extraction to installation would remove the runtime Git/repository prerequisite, but needs a separately reviewed installer and immutable provenance record binding source commit, exact extracted bytes and installed payload; that installation boundary is not supplied by this cut.

## Records · `sec:credentialcustody:records`

Each input form is strict versioned JSON limited to 262144 bytes: observation schema 3 and discovery schema 1. Observation records serve `length-observe` and `identity-check`; discovery never parses that campaign shape. Every object rejects unknown and duplicate keys, missing members and wrong types. Later commands need a separately reviewed schema version; ignored extension fields are not permitted. The campaign top-level fields are `schema`, `case`, `campaign`, `sealed_root`, `evidence_root`, `payload`, `limits`, `identity`, `probes`, `names`, `lengths`, `contents`, `comparisons` and `samples`. Names contain at most 96 ASCII letters, digits, dots, underscores or hyphens, excluding dot and dot-dot. Paths are explicit and reject traversal. No field carries plaintext, a credential, or a secret-bearing argument.

`payload` names an installed `path`, full `sha256`, source `repository`, forty-character `source_commit` and repository-relative `document`. The observer extracts single-quoted heredoc bodies from that exact committed document with Git replacement objects disabled and requires exactly one body matching both the reviewed digest and installed payload bytes. It runs those bytes with fixed `/usr/bin/python3 -I -`, followed only by sealed-root, wrap-width and final-LF metadata. The stdin here carries reviewed program source, never plaintext or a counting stream. The record cannot substitute a Python executable, module, command string or shell. The estate supplies and installs its reviewed payload; this repository ships only a synthetic test stand-in.

`limits` gives `file_bytes` (1–16777216), `output_bytes` (1–4194304 per child stream) and `timeout_ms` (1–60000 per child). Children receive an empty environment (Git alone receives the fixed empty transport allowlist), explicit standard streams, empty input for probes, bounded captured stdout/stderr and finite cancellation. At single-threaded startup, every inherited descriptor from 3 upward is marked close-on-exec using Linux `close_range`; failure refuses before any child starts. Files opened by the observer are also close-on-exec. Child exit is observed with `waitid(WNOWAIT)`; the process group is killed while its leader PID is retained, and only then is the leader reaped. Startup restores the default SIGCHLD disposition to prevent automatic reaping. Nonzero child status, any stderr, output overflow or timeout refuses without relaying foreign diagnostics. The interpreter digest is included in the identity. The file that supplied that digest stays open until execution; its device and inode must equal the checked execution anchor, or `interpreter-execution-identity` refuses before spawning. Byte-identical replacements still refuse. The source document and installed payload are both bounded.

`identity` contains `measure` (`decoded-length`), `computation` (`3*(N/4)-P`), `form` (`wrap`, `final_lf`), `files`, `probes` and `source_commit`. `files` requires `sealer`, `library`, `interpreter` and `parser`, each with `path` and full `sha256`. Interpreter path is fixed to `/usr/bin/python3`; its resolved regular-file bytes are hashed. Other identity files reject symlink traversal. All four file paths must be distinct (`record-file-identity-distinct`), and the four opened files must have distinct device/inode pairs (`identity-file-alias`); identical content alone does not make two files aliases. Each identity probe has `role` and a full lowercase `sha256` digest of its exact output bytes. Raw probe output is bounded and transient; it is never serialized into a result or receipt. Digests are chosen over an output grammar because arbitrary reviewed probe vectors need not share a textual grammar. The parameter `probes` give `role` and exact `argv`; both rosters require exactly boot, deployment, live-applied, sealer-version, sealer-package, library-mapping and interpreter-package. Probe digests cover every byte, including final newlines; missing or empty output refuses. Observation records use schema 3 and old record forms refuse without migration; discovery remains schema 1. The deployment owns the package and library mapping commands and their meaning; this tool embeds no distribution or package manager.

`names` contains 1–16 distinct names, `lengths` 2–16 distinct bounded input lengths, and `contents` exactly two distinct public pattern identifiers. `samples` must cover their full product exactly once. Each sample has `name`, `input_length`, `content` and the producing child `case`. The first content label denotes the ascending internal pattern, the second descending. Every measured campaign output must map exactly once to the name/length/content grid and agree with its public case. No success, distinctness or sealed-digest assertion is accepted in a sample. Files are named ``NAME/LENGTH-CONTENT.sealed`` beneath the sealed root. `comparisons` contains bounded distinct `id`, `left` and `right` pairs drawn from the name roster. Equality across different names is recorded, not required.

`campaign` has exactly a protected launch-policy `policy` path and full `matrix_sha256` reference. The observer reuses launch admission to measure current policy, public cases and held artifacts, then reads the protected schema-2 completed matrix and original outputs. Sealer, parser, interpreter and library identities must match those measured artifacts. The result retains campaign, matrix, policy, code and measured-configuration bindings plus a domain-separated digest of the typed observation parameters, including exact probe vectors and file form. JSON whitespace is not parameter identity. Caller assertions `config_digest`, `code_digest` and `completion` are refused rather than reinterpreted. Recovery or failure records never supply calibration acceptance.

The operator prepares an immutable sealed-only analysis view under the separate `sealed_root`, disjoint from all campaign roots: byte-for-byte copies, no links, decoded data or plaintext stream. This bridges the original case/output layout to the reviewed parser's name/length/content layout without changing its bytes or row contract. Each copy's length and digest is checked against its measured original before and after parsing; campaign admission is rechecked afterwards. Reserve disk for both sets and retain the original matrix, completed receipts, policy, public cases and artifact installation for the calibration's validity lifetime. Dispose of both views only when retiring that calibration. This tool does not create the analysis view or provide a copy command.

## Length and identity · `sec:credentialcustody:length-identity`

The reviewed parser emits space-delimited metadata rows: `NAME LENGTH CONTENT file-bytes N wrap W final-lf F base64-chars N padding P decoded N offset N`, one `NAME constant N` per name, and one `ID same-constant-both-names True|False` per comparison. Complete rows, exact roster, numeric consistency, observed text sizes and the fixed form are mandatory. For a nonempty encoded body of N characters, file bytes must equal N plus the frozen newline count: final-LF (0 or 1), plus `(N-1)/wrap` when wrap is nonzero (`payload-row-inconsistent`). One decoded-minus-input constant must hold across all lengths and both contents of each name. The payload rejects whitespace normalization, wrong wrapping/newline form, alphabet or padding. Sealed digests are checked before and after execution; identity is checked on both sides. No decoded bytes are materialized by the observer.

`format-discover` takes a separately tagged record with exactly `schema:1`, `command:"format-discover"`, `case`, absolute `input`, `evidence_root`, and `file_bytes` (1–16777216). Its own case has no campaign roster, completion assertions, parser or probes. The single input is immutable under the same file custody rules; its parent is private with protected ancestry. No child is spawned. The envelope label is `format-discover` and outcome is `observed`, never a successful length observation. The former `length-observe --discover` option is refused. Discovery reports only `line_count`, `wrap_width` (null for irregular wrapping), `final_newline` and `alphabet_conformity`, with `discovery:true`. It cannot create a calibration or accept a length. Alphabet conformity is a representation observation, not a padding or length verdict. The operator must freeze a separately reviewed form before calibration.

`identity-check` requires a complete immutable length-observation receipt with schema 2, matching case, measured campaign/parameter identities and row matrix. Old calibration envelopes refuse; no compatibility reader exists. It reopens the completed campaign binding and original sealed bytes. It compares every declared identity member against live probe output and file digests, refusing drift or absence even when constants match. It emits `matches:true`, the compared receipt digest and the measured campaign binding; it never edits or repairs calibration.

## Publication and output · `sec:credentialcustody:publication`

The executable declares `machine-json`. Success emits exactly one object plus LF with `schema`, `command`, `case`, `outcome`, `wall_us` and `evidence`: schema 2 for `length-observe` and `identity-check`, schema 1 for discovery and launcher result envelopes. Runtime failure returns 1 with empty stdout and one classed, redacted JSON diagnostic; invalid command-line usage and terminal stdout return 2. Help and version use shared JSON control records on stderr. Panic payloads and foreign errors are suppressed. Output-write failure is failure even if a receipt has already been published.

Receipts are exclusively created as ``.NAME.partial`` at 0600 beneath an existing caller-owned 0700 evidence directory. The writer flushes and synchronizes bytes, sets 0400, synchronizes again, then publishes with Linux no-replace rename and synchronizes the directory. Existing destinations and partial candidates refuse; partial files are never acceptance. Final receipt names reserve leading dots and the `.partial` suffix. Calibration inputs must name a final receipt beneath the declared evidence root. A failed publication can leave a complete disk receipt, so retry inspects retained state rather than assuming nothing happened. Tests exercise caller-owned synthetic files only and make no encryption, supervisor, root-installation or power-loss claim.

## Refusal controls · `sec:credentialcustody:refusal-controls`

Malformed alphabet, padding and representation controls assert `child-failed`: they witness the reviewed parser boundary, not the Rust constant validator. A separate synthetic payload emits a complete row matrix with inconsistent offsets and no Python constant assertion; it must reach `length-condition-refused` in the observer. Invalid parameter computation/measure assert `record-computation`, while altered calibration computation/measure assert `calibration-identity`. Live probe drift asserts `identity-drift`; artifact drift may refuse during fresh campaign admission before the probe runs; a changed recorded form asserts `calibration-identity`.

Tests must use a `TMPDIR` beneath the running user's protected node directory: a foreign-owned or nonsticky group/other-writable ancestor causes `directory-ancestor-custody` before the tested operation. The shared `child-failed` class identifies the parser in malformed-file controls only in conjunction with the passing `known_lengths_and_identity` control using the same fixture and reviewed programs.

## Rehearsal fixture · `sec:credentialcustody:fixture`

`credential-fixture emit --case-record FILE` is a separate, non-installed executable in this package. Meson builds ``packages/superloop-credential-custody/credential-fixture`` and ``credential-fixture.build.json`` inside the build tree with the package release identity; neither is selected by ordinary installation. A rehearsal operator obtains both from an independently reviewed tagged build, checks the build record and full artifact digest, and explicitly stages it in a new immutable artifact directory: root-owned directories 0755, executable 0555 and build provenance 0444, beneath resolved protected ancestors. Verify installed version, digest, mode and security label, and retain the staging read-back before use. The fixture case remains a separate public record: either effective-user-owned with mode exactly 0400, or root-owned with mode exactly 0444 for a manager-allocated execution identity. No tenant map installs or calls it. The fixture refuses effective root (`fixture-privilege`); the observation commands' authority table remains separate.

Its public case has exactly `schema` (1), `command` (`fixture-emit`), `case`, `streams` (exactly two objects), `behavior` and `timeout_ms` (1–60000). Each stream has `name`, `length` (1–1048576) and `pattern` (`ascending` or `descending`). Names and patterns must be distinct. Ascending byte i is i modulo 251; descending is 255 minus that value, so every tested positive length has different contents. The record never contains output bytes. Unknown, duplicate, missing and wrongly typed fields refuse. Both forms require a regular single-link file, the 262144-byte bound and the existing protected symlink-free ancestor walk. Only this fixture reader accepts root-owned 0444; observation parameters and calibrations still require their private 0400 class. The strict public schema admits no credential bytes, key, environment, arbitrary input path or other extension. The root-owned 0444 class additionally requires root-owned ancestors, using the same protected walk, so its `DynamicUser` reader cannot replace a path component. A root-owned file is staged under protected read-only public directories; rehearsal witnesses `DynamicUser` read access and directory listings containing only the public case, without a credential-store mount. Ordinary-user tests cover the exact owner/mode predicate and actual file/walk refusals; they do not claim to create host-root-owned input. This is not a campaign-record variant.

The supervisor supplies `LISTEN_PID` equal to the fixture's exact decimal PID, `LISTEN_FDS` exactly `2` and `LISTEN_FDNAMES` containing exactly the two case names, colon-separated in descriptor order starting at 3. The fixture checks only those two slots: both must be distinct writable pipe objects opened write-only. Missing, wrong, repeated or extra convention members refuse before generation. Additional descriptors outside the convention are the external observer's responsibility; the fixture never enumerates its own descriptor table. The fixture does not close descriptors it inherits beyond the convention: they stay open until the barrier, where the external observer must refuse them, so a supervisor passes exactly the standard streams and the two named slots. After validation it stops itself with SIGSTOP, before generating any byte or opening an unrelated resource. The supervisor observes the stopped process and sends SIGCONT. The two streams are generated directly into the pipes, closed before a success envelope, and never copied to arguments, environment, logs or stdout. Backpressure is bounded by a deadline beginning after release; broken or blocked streams fail. The external supervisor must also bound the stopped interval and collect EOF and exit status.

`behavior` is `normal`, `short`, `excess`, `partial`, `fail-after-output` or `reexec-extra`. Short and excess change the first stream by one byte; partial writes half of the first and none of the second; fail-after-output writes both complete streams. All four return failure with `fixture-injected-failure`, never a success envelope. Reexec-extra opens only the harmless null device without close-on-exec, preserves the two named streams, and re-executes the pinned fixture image before stopping; its extra descriptor is visible to the external observer. An internal PID/descriptor marker prevents recursive re-execution and is validated against the null device. These deliberate behaviors exist only in this artifact. The normal startup close-on-exec rule remains in force; only the deliberate re-exec's three known descriptors are cleared for that exec.

The Rust test harness supplies the convention, waits for the stopped process, proves both pipes are empty before release, enumerates descriptors from outside, continues the fixture and collects both streams and its actual status. This proves the fixture's side only: it does not establish launcher wiring, manager-held descriptor lifetime, production-generator startup containment, privilege separation, sealing or a real supervisor's completion evidence. The next slice must supply those observers and reject the deliberate extra descriptor before release.

## Private launcher cores · `sec:credentialcustody:launcher-cores`

The four root-only command adapters reuse the policy, measurement, state, manager and keeper cores directly. Ordinary-user tests invoke private owner and process adapters; no installed flag selects those adapters. Admission requires a root-owned 0400 launch policy through the protected ancestor walk. The installed boundary checks the host user map, all four uid values, exact role capability sets, no-new-privileges and the running launcher image against the measured artifact. Actual loaded mount and manager-access confinement remain operator witnesses before a root rehearsal.

The separate strict `launch-policy` schema 2 has `campaign`, `roots` (runtime, sealed, evidence), exactly two `manager_sockets`, `host_key`, `slice`, `limits`, `artifacts`, five typed unit `roles`, the closed `sealer_construction` value `landlock6-seccomp-v1`, and `cases`, in addition to its schema and command tags. Unknown, duplicate, missing and wrongly typed fields refuse. Paths are absolute, resolved and limited to ASCII letters, digits, slash, dot, underscore and hyphen; roots are disjoint and cannot contain artifacts, public cases, the key or manager sockets. Case IDs, unit names, public-case paths, artifact IDs and artifact paths are distinct within their rosters. Each case binds its separately tagged public file and expected digest, exact unit and two distinct stream names, output leaves and internal patterns. The policy carries no arbitrary command vector, unit property bag, environment or sentinel bytes.

Limits are finite and checked before filesystem effects: at most 64 cases, two outputs each and 16 distinct stream names; case deadline at most 600000 ms, campaign deadline 3600000 ms and poll interval 1–1000 ms no greater than the case deadline; output ceiling 16777216 bytes and campaign ceiling 2147483648 bytes; diagnostics 16384 bytes, artifact 67108864 bytes, observed descriptors 5–64, mapped files 1–128 and event queue 1–256. Stream lengths are 1–1048576 bytes. Every ceiling is nonzero, and the campaign must cover the sum of case deadlines and both output ceilings per case. The 262144-byte input bound limits parsing. Artifacts comprise exactly one launcher, fixture, sealer, parser and interpreter, one or more libraries up to the mapping ceiling, and an optional all-or-none manager-start/manager-query pair; the maximum is 135. The optional pair admits neither a transport nor a dependency.

The closed role matrix requires an empty ambient set, no-new-privileges, strict filesystem protection, host user/PID namespaces and private diagnostics. Calibration-run has observation and signalling capabilities plus manager access; descriptors has observation capability unconditionally; barrier-release, completion and fixture request empty bounding sets; only the keeper performs continuation. Direct sealer construction is a required closed value separate from unit roles; the obsolete sealer unit role and schema-1 launch policies refuse. Direct sealers inherit the keeper bounding ceiling; their effective, permitted, inheritable and ambient sets are cleared, and no-new-privileges prevents regaining them. Their actual confinement is the Landlock/seccomp construction below. The construction value selects the existing fixed child restrictions; it is not evidence that a child applied them. Only the fixture uses a manager-allocated non-root identity. Writable roots are typed per role. These are requested and compared properties, not granted authority. Root retains owner access even without capabilities; a root keeper connected to the manager has the manager's broader authority. Standalone observer/release/completion and sealer confinement must also make both configured manager sockets inaccessible. The adapter measures files and effective sets and checks execution vectors, descriptor mapping and limits. The operator must additionally retain the installed roles’ loaded paths and mounts and their inability to access either manager socket; a boolean declaration alone cannot establish that confinement.

Admission hashes bytes from held artifact descriptors after protected traversal and regular-file, owner, mode, nonzero-link, size and alias checks. Root-owned packaged artifacts may have multiple links; special bits and group/other write refuse. File identity and size/time metadata remain checked through retained descriptors. Public-case files require exact owner, 0444, one regular link and the input bound; their measured bytes must match both the reviewed digest and the fixture schema's case/stream/timeout binding. Protected policy bytes, actual artifact bytes and public-case bytes produce the receipt identities; expected digests are comparison references, never substituted measurements. Artifact aggregation is sorted, domain-separated and length-framed. Typed observed role properties are compared and separately hashed as exact received bytes and canonical metadata; raw foreign properties are never copied to receipts. The private manager adapter below obtains those values from the queried unit reply; an installed-manager witness remains required. The current private configuration core covers the role matrix; live execution/mapping/limit normalization belongs to that adapter.

Reservation uses an admitted case index and cached fixture image, creates new 0700 case directories under held private sealed/evidence roots and two exclusive 0600 output files, then publishes an immutable creation manifest with device/inode identities and measured digests. Existing objects refuse. State receipts use the shared 0600 partial, flush/fsync, 0400, no-replace rename and directory-sync protocol relative to held directories. Captured invocation metadata binds unit, nonzero invocation/PID/birth/uid and measured image before release stages become reachable. Release cannot repeat, terminal state cannot recover to success, and publication failure makes the in-memory state uncertain. Finalization requires the EOF/sealer-complete state, bounded nonempty outputs, matching held objects, fsync and 0400 before a complete state can be published. These state cores accept later adapters' observations; the C2 pipe/sealer core below witnesses only channel EOF and sealer exit, never encryption or generator success.

A binding failure during a transition or output synchronization irreversibly latches uncertainty and attempts an immutable uncertain receipt naming its static refusal class without checking the lost outputs again. Failure and uncertainty transitions require an explicit internal refusal class; no child diagnostic bytes are retained. If the evidence directory itself cannot be verified or publication fails, the state remains uncertain and cannot resume success. Restoring an original output never clears the latch. Failure creates no credential marker. Cleanup is terminal-only, verifies the entire two-output creation manifest before unlinking any member, and never scans a root or deletes unrelated files or receipts. A failure before a durable creation manifest leaves private incomplete objects for operator quarantine; cleanup does not guess ownership from a name. Path replacement refuses. Installation and configuration must remain frozen against writes by their trusted owner, including root; held inodes do not prevent that owner from rewriting content. Parsing/indexing and artifact hashing happen once per admission; each reservation and transition touches only that case's two outputs and bounded receipts. No manager, global process or historical directory scan is introduced.

The private campaign core reserves an immutable campaign start before running cases in declared order, with one pair resident at a time. Each child identity binds the campaign, measured policy and public case, and index. A callback returning success is insufficient: the store must retain successful invocation-bound completion evidence, matching immutable output sizes and an unchanged completion receipt. A failure stops the remaining cases and publishes only a refused prefix. The final bounded matrix is an observation receipt, not calibration acceptance; sealed-length integration remains separate. Campaign and child collisions refuse rather than regenerate. The full completion receipt digest binds later references to the bytes compared against the store’s independently retained snapshot; a substituted child receipt cannot rewrite that reference. The calibration-run adapter supplies the resident keeper callback; it never shells out to other custody commands.

Private-core tests cover strict shape, finite bounds, the role matrix, measured-byte drift, alias and custody refusals, public-case binding, invocation/configuration mismatch, exclusive creation, immutable receipts, terminal transitions, replacement and manifest-bound cleanup using synthetic caller-owned files. They prove neither host-root installation nor manager authority, capabilities, durable power-loss behavior, encryption or cross-uid observation. Those remain separate live-adapter and rehearsal witnesses.

## Pipe and sealer core · `sec:credentialcustody:sealer-core`

The private C2 session accepts exactly two distinct, already-open, blocking pipe or FIFO read ends; it neither creates their paths nor reads their plaintext. A dedicated read-end duplicate has only a zero-timeout readiness observation method, with no reading or descriptor-export interface. Only HUP without readable data or error is closed-and-drained; HUP with buffered bytes refuses completion. Pidfd readiness and nonblocking stderr draining share one event wait. Each sealer exit rechecks its pipe, so early zero exit with a retained writer or buffered remainder refuses without waiting for a producer to write. No timeout becomes EOF. A single absolute case deadline bounds the wait and cannot be extended by retries or an injected caller deadline.

The session selects C1's measured sealer artifact and executes the fixed vector `encrypt --with-key=host --name=NAME - -` through the existing held-descriptor executor, with a second inode match to the retained measured file and unchanged metadata checks. It passes the input capability directly as stdin and the manifest-owned empty 0600 output as stdout. It clears the environment, constructs child descriptor inheritance through the shared owner, sets no-new-privileges, clears effective/permitted/inheritable/ambient capabilities, disables core dumps and applies the admitted sealed-file size limit. Stderr is read into a fixed 4096-byte scratch buffer, counted against the admitted ceiling and discarded; no raw diagnostic byte is retained in a result, receipt, argument or log. Native exit codes and signals are metadata, never shell status text. The child additionally enforces the confinement below. Root namespace, host-key admission and real installed-manager observations remain root-rehearsal obligations; this private core grants none of them and does not grant its caller any capability.

A successful session returns bounded nonempty sealed sizes and retains zero-exit observations, but makes no case transition after its sealer-started publication. The private keeper advances C1 through the session while sealers remain alive. It cannot publish calibration completion. Short and excess inputs may both drain normally: decoded-length acceptance belongs to the later observation integration. Generator failure after complete sealer output still requires a typed failed case. Admission refusals before spawning create no child and leave the already-reserved case for the keeper’s typed failure handling; binding loss still latches uncertainty immediately. Failure while starting either child is owned by the session and cancels any child already started. Cancellation, abandonment, early exit, diagnostic overflow and sealer failure cancel process groups before their leaders are reaped, then use the typed C1 failure receipt and manifest-gated cleanup. Lost output custody instead latches uncertainty; publication or cleanup failure retains private quarantine, never a marker. Each active session owns two children, two probes and bounded diagnostics; its work does not scan other cases or the descriptor population.

Cargo builds ``tests/support/sealer_native.rs`` as the `custody-sealer-test` example for package tests. It is neither a public command nor a rehearsal artifact, has no Meson staging or install target, and enters no versioned-program roster. The existing source inventory, public set and package owner cover it. Its stdin/stdout/stderr contract is the same, but its output is synthetic padded base64, not encryption. Fault cases live only in this native test image. Capture contradictions latch uncertainty, so a later invocation cannot repair missing evidence. Terminal receipts preserve the first cause in `original_cause` separately from the current `refusal_class`, including loss of output custody or failure to publish a receipt.

## Child confinement · `sec:credentialcustody:child-confinement`

Before starting either sealer, the private core requires Landlock ABI 6 or newer and creates a ruleset handling all filesystem rights through device ioctl, including rename and truncate. It never reduces the policy for an older kernel. The admitted key parent directory must be root-owned, have no group/other write or special mode bits, and pass the protected ancestor walk; 0755 is accepted. The key is a root-owned 0400 regular file with exactly one link, held with `O_PATH` without reading its bytes. Production admission first compares the policy path with the native sealer’s fixed host-key path. Only that file gets read-file rights and its parent gets read-directory rights; the measured sealer and library artifacts get read-file/execute rights. The record must enumerate the native loader and every library the sealer needs. No filesystem write right is granted. The sealed output is already open, and remains writable by descriptor. A missing kernel interface, allowance or required file is a refusal, never a broader fallback. Ordinary-user admission tests may use root-owned library artifacts; production admission already requires root-owned artifacts throughout.

After no-new-privileges and capability clearing, the child applies Landlock and an architecture-checked seccomp filter denying socket and socketpair creation for every address family, and denying `io_uring` syscalls so they cannot supply an alternate socket-creation route. The filter refuses a foreign syscall architecture and the x32 syscall convention. These are per-child mechanisms: the sealer is a direct child and does not acquire a separate service-manager unit or filesystem view. The keeper's unit properties cannot substitute for this child policy. The filter also denies permission, ownership, timestamp and extended-attribute changes, which Landlock does not mediate: a sealer must not make an evidence file writable to another account. Signal and abstract Unix socket scopes restrict outbound operations to the same or a nested Landlock domain. They do not restrict the unconfined keeper signalling its children; cancellation tests observe both sealer exits as SIGKILL. Abstract socket scoping does not revoke a previously connected socket, but no socket is inherited here. Seccomp permits resource-limit operations only with pid zero (self) and denies scheduling and IO-priority changes entirely. The probe signals an outside same-uid control child and tries to change its core limit; both refuse, while self signalling and a self limit query succeed. The filter denies kernel keyrings, every native System V IPC syscall and all POSIX message-queue syscalls. Named POSIX shared memory and semaphores also remain inaccessible through the filesystem policy; no such descriptor is inherited. The probe uses invalid IPC selectors and checks refusal before argument validation, so no host IPC object is created or modified, and no IPC payload is read, even by a mutation. This bounds the named authorities, without claiming that every kernel operation is sandboxed.

The test-only `custody-confinement-probe` Cargo example uses the identical child construction with a synthetic image and paths. Its fixed metadata result witnesses denied Unix/IPv4/IPv6 sockets, socket pairs and ring creation, denied write opens on an outside canary and an evidence file, denied creation in the key directory, successful read of a synthetic key and listing of its directory, denied read of a sibling file, denied evidence permission changes and successful write to preopened stdout. It is neither staged nor installed. This exercises actual kernel restrictions as an ordinary user; it does not witness host-root ownership, a host key, the manager's loaded unit properties or installed-manager FIFO lifetime. Those remain operator rehearsal gates.

## Retained keeper and administrative core · `sec:credentialcustody:keeper-core`

The private keeper joins admission, exclusive outputs, protected FIFOs, confined sealers and the held manager adapter through the stopped capture phase. The finite per-artifact maximum is 64 MiB; each policy retains its explicit lower allowance. A fresh single-threaded root entry guard checks the host user map and closes every inherited descriptor from 3 before acquiring owned case resources. It validates both FIFO objects before unlinking their paths and closing keeper writers. Captured receipts additionally retain hashes of the actual manager reply and normalized observed properties. Any contradiction quarantines the case; ambiguous manager submission or failed invocation-bound stop retains outputs. Cleanup can run only once, uses the existing manifest checks and never substitutes another invocation. The private observer, release and completion cores below extend capture; the root-only command adapters use these cores; credential-set markers remain excluded.

The schema-1 request contains only schema, case, `keeper_pid`, `keeper_birth`, invocation, operation (status, completion, or the separately bounded pidfd handoff) and a 32-character lowercase hexadecimal nonce; unknown fields, duplicate keys and other operations refuse. The client half-closes its write side to frame at most 4096 bytes ending in one newline; replies echo that nonce and contain at most 4096 metadata bytes. The case deadline caps every transaction; the caller may shorten it and supplies an event-loop bound; no unbounded server loop or client command is wired. Cleanup verifies the socket's owner, exact mode, single link and inode.

Tests use real stopped ordinary-user children, pidfds, procfs identities and Unix peer credentials. The native manager peer records vectors and supplies synthetic properties; test-owned duplicates stand in for cross-uid `pidfd_getfd`, and the harness itself kills and reaps every child. These tests do not prove root observation rights, manager FIFO writer lifetime, loaded sandbox properties or host-map access by separate privileged roles. Before a root rehearsal, the operator must establish those installed-manager witnesses and run the identical confined child construction's negative control with the real loaded files. The completion client authenticates the protected keeper manifest, socket and connection-bound handle without reading a capability-bearing keeper's procfs image.

The ordinary-user keeper harness admits the small native manager example as its control-client image. A test-only binder pins the Rust test runner by its actual process image while preserving the admitted client image; the production binder still requires the keeper itself to match the admitted launcher image, and a wrong-image control asserts that refusal. Native clients exercise the actual socket credentials and image comparison. This avoids hashing the development test binary as a production artifact.

The build-only `custody-startup-test` Cargo example retains the exact entry guard and descriptor-closure control separately, so the native manager/control peer does not link that unused dependency closure. Neither example is staged or installed.

Fixture harnesses observe a stop or early-exit event under a 600-second emergency guard. Ordinary parser/probe fixtures use the existing 60-second policy maximum as their hang allowance. The timeout control reads a pipe whose writer never writes; exception and output-limit controls use the longer allowance and assert their distinct diagnostic classes. No assertion compares elapsed time.

Sealers cannot change process groups or sessions. Cancellation kills the retained group before reaping and independently signals the leader through its retained pidfd, so a changed group cannot strand the keeper in its leader wait. The pre-pidfd setup-failure path also kills its still-unreaped child directly.

The private descriptor observer inventories only the held stopped fixture, with bounded metadata reads before and after process verification. It requires read-only null stdin, write-only null stdout/stderr and exactly two distinct write-only stream objects matching their creation order; an extra descriptor refuses even when close-on-exec. The test harness opens the same null devices and modes as the submitted manager template. Sealer read-back observes each child’s uid values, empty effective/permitted/inheritable/ambient capability sets, no-new-privileges and seccomp mode 2. Its bounding set must match the keeper’s measured inherited ceiling; it is not claimed empty. The descriptors adapter receives the observation-only handle and verifies the captured process; it grants no capability.

The private release core publishes a retained 0400 inventory receipt with captured invocation, boot, descriptor objects, direct-child status and measured configuration. Release reobserves these bindings, checks the protected receipt object and full digest, synchronizes release intent, then rechecks the absolute case deadline and sends SIGCONT only through the retained pidfd and publishes the released state. This is not a completion witness; the barrier-release adapter requests this sole keeper-owned transition.

The integrated ordinary-user controls execute a private copy of the built fixture after `strip --strip-debug` removes development symbols, keeping the admitted executable below the unchanged 64 MiB ceiling; its actual stripped bytes are measured. Completion/status transactions receive no descriptor. ## Private completion core · `sec:credentialcustody:completion-core`

The keeper observes one active case at a time. It requires the captured invocation and execution pid, the same nonzero start timestamp and loaded configuration, true condition and assertion results, and a retained pidfd exit event. Only a loaded oneshot holder in active/exited state with normal exit zero and a nonzero exit timestamp can succeed. A complete still-starting reply is pending, even if process exit arrived first; missing/default fields, stale success, unloaded units and transport loss cannot substitute for execution. No start-command exit or absent job is treated as generator success. The selected CLI route compares execution properties rather than claiming a bus job-result subscription.

The existing immutable state receipt retains the allowlisted manager result name, typed generator exit evidence and measured manager reply/configuration digests before holder cleanup. Only the keeper stops the matched holder, once; under `OpenFile` this is cleanup, not the cause of EOF. Completion then requires both poll-only EOF observations and both successful sealer exits, followed by output and directory syncs and mode 0400. The final state receipt is named ``completion.json`` and is exclusively published. A failed publication or full generator output followed by failure cannot be accepted. This is process completion, not a decoded-length, encryption or calibration-validity claim, and never a credential-set marker.

Ordinary-user controls run real stopped fixtures, pipes and native synthetic sealers against explicit native manager replies. Replies change after process events, not sleeps; delayed metadata remains pending and terminal contradictions latch uncertainty. The installed manager's retained-result and writer lifetime, actual role confinement and power-loss durability remain operator witnesses. The completion adapter opens the protected binding and polls retained views while the resident keeper owns manager queries and holder cleanup.

The private completion transaction serves only the keeper’s retained in-memory view; it neither queries the manager nor stops or releases a process. The client checks the protected manifest’s keeper uid/pid/birth, case and invocation. After pinning the connection peer with its kernel pidfd, it measures that process’s start time from procfs and compares it with the manifest; it never substitutes the peer’s echo for that measurement. The request writer obtains a new 128-bit nonce from the kernel random source for each transaction and checks its echo. The nonce correlates a reply, and start time detects stale identity; neither replaces socket custody and peer authentication. The connection’s own pidfd must remain live across parsing. Complete requires the captured generator identity, successful execution and both EOF/zero-exit sealer results with bounded nonzero sizes; pending and failed phases cannot accept an old success. Closed metadata replies carry no descriptor or child diagnostic. The installed adapter uses the protected client opener; production callers cannot supply a nonce or use a receive-only completion API. No connected control socket is passed to another process.

A valid terminal observation is retained before the post-observation deadline check, including failed generator results. Expiry then refuses acceptance while preserving evidence before matched-holder cleanup. Manager construction and stopping belong to the keeper’s private module; the campaign cannot create an independent cleanup owner. Pending manager replies require bounded polling at the policy interval after pidfd exit, not an event the command-line transport does not provide.

Launch-core tests share one case guard across their modules only for retained admissions, stores and child cases, without increasing the process descriptor limit. Pure policy, state, status and record parsing and small standalone pipe controls run without that guard. The guard control checks mutual exclusion directly; battery wall measurements are observations, never acceptance thresholds. Descriptor measurements describe retained handles at case stages; they do not establish the cause of an earlier loaded-run failure.

Failed file opens, descriptor duplication and child spawns retain numeric kernel context at the operation: errno, open-descriptor count, soft/hard ``RLIMIT_NOFILE``, live thread count where readable and the configured test-thread count in unit tests. The final diagnostic message keeps its refusal class and appends ``; kernel=`` followed by JSON for the most recent kernel refusal, whose own class is explicit. It includes no path, argv, environment value, raw OS error string or child output. Unit-test failures also print this metadata at capture, before unwinding can close the case. Counts are observations in a concurrently changing process, not atomic snapshots or acceptance conditions. If procfs cannot be opened, a descriptor-free scan covers at most the hard limit or 1048576 slots and reports its ceiling; higher retained slots after a lowered limit may be outside that range. Unavailable measurements are null, never zero. A process-wide baseline assertion at guard release would confuse concurrent unguarded pipe tests with leaks; the isolated case-stage control retains its explicit final-baseline check instead.

The private completion client opens the immutable control manifest and exact 0600 socket beneath a held protected case directory. It compares policy, public-case and captured invocation bindings, pins the connection peer with the kernel handle and measures its start time without reading the keeper executable. It rechecks the directory, manifest object and bytes, and socket before and after the existing nonce-owning completion transaction. It never forwards the connected socket or accepts an old completion file in place of a live keeper. The installed completion adapter retains that same manifest across pending retries and acknowledges only a complete observation.

The private administrative transaction core accepts versioned inventory, release and completion-observed requests through the same protected socket and connection-bound peer check. Inventory and release peers must lack the signalling capability in every set, including the bounding set; authorization is checked when accepting and can be rechecked immediately before an effect. An owned transaction holds the peer and socket while the keeper works. The legacy status endpoint refuses these requests. The installed adapters use these messages to request the same keeper-owned cores; completion-observed is post-completion flow control, not evidence or permission to stop a holder.

The private resident driver owns one keeper through start readiness, capture, inventory, release and completion. Start readiness permits only complete property-checked activating metadata; pre-execution fields are pending, never completion evidence. Once observed, the invocation cannot change or disappear. The existing stopped-process capture still measures the image and command. Pending replies are polled at the policy interval within the case and campaign deadline. The same keeper serves authenticated requests, observes generator exit, retains evidence, stops its holder and checks both sealers. It remains live until a read-only client acknowledges its already-complete observation; that acknowledgement cannot supply success or stop or release a child. A missing acknowledgement prevents campaign acceptance. No command bypasses root admission, and ordinary-user tests invoke private cores through adapters.

A client cannot substitute an old receipt for a live keeper. Missing clients, wrong ordering, a changed binding or a deadline refuse the campaign; no final matrix is published for an incomplete pair. Completion keeps one protected manifest across reconnects and acknowledges only after validating the live retained generator and both EOF/exit results. This acknowledgement allows keeper exit and supplies no success evidence.

Every launcher command refuses an ordinary uid before opening policy inputs. ## Campaign failure evidence · `sec:credentialcustody:campaign-failure-evidence`

A failed or cooperatively stopped campaign publishes schema-4 ``campaign-failure.json`` in its evidence root, naming the failed child and index, the campaign stage, the first case failure stage and cause, and the last immutable lifecycle receipt. A failure before case reservation has no case receipt; a failure after a complete child preserves that child's completion. The diagnostic carries the same locator and whether the campaign failure receipt was published. A failed publication is not evidence that recovery completed. No lifecycle file or failure summary supplies calibration acceptance: use the protected completed-matrix handoff reader.

Within each case's evidence directory, ``state-00.json`` records the reserved objects and subsequent ``state-NN.json`` files record acceptance transitions, ``inventory.json`` records the external descriptor observation, and ``completion.json`` records successful process completion. The separate ``lifecycle-NN.json`` sequence has at most 16 exclusively created 0400 entries. It records submission acknowledgement, the first fully compared start binding before in-memory adoption, recovery intent and observed cleanup results. The runtime directory holds ``fifo-manifest.json`` and ``control-manifest.json`` for the named FIFO and socket bindings. Sequence numbers are local to that case. Read the highest published sequence; a ``.partial`` file is never a receipt. Lifecycle publication checks the held evidence directory and never overwrites an earlier record or reopens acceptance after uncertainty.

The start-binding event retains the invocation and the measured manager reply and configuration digests even while execution is still pending. Recovery results preserve the first cause and distinguish a completed stop job under that invocation from an absent unit; successful unlink from retention or unknown state; and a sealer exit observed through its held handle from no observation. A stop-command exit never claims the unit record was removed. Secondary cleanup failures remain visible after an uncertain latch. Retained means the tool did not remove the resource, not that its pathname still names the original object. A failed case reservation can leave directories or files before its creation receipt exists; these remain unresolved and must not be removed by guessing. Unknown, unbound, failed and retained resources require operator reconciliation; no missing field or missing terminal record means success. Completed outputs and evidence are preserved.

To stop intentionally, verify the keeper unit and its live main process, then use ``systemctl kill --kill-whom=main --signal=SIGTERM KEEPER.service``. Do not stop the whole unit unless its owner-approved stop template gives the keeper time to recover. The single-threaded keeper consumes SIGINT and SIGTERM through a signal descriptor: schema-2 lifecycle records and the failure summary retain the first sender pid, uid and signal, and count later consumed requests. Standard signals can coalesce, so this is not a count of all sends or an authentication claim. The outcome ``stopped`` means the bounded recovery attempt ended, never that resources are absent. Recovery has one fresh ``case_ms`` allowance shared by completing the same admitted start comparison and stopping its bound invocation. It never stops by name alone; an unresolved binding retains its refusal class. Child execution restores the pre-listener signal mask. A published matrix is not revoked by a later stop request.

Never interrupt a waiting client: a closed connection refuses the case, and a lost reply never permits blind repetition of an effect. Read ``campaign-failure.json`` and its named lifecycle receipt for the last phase, original cause and secondary cleanup facts. After a killed keeper, preserve evidence and run ``systemctl show --property=InvocationID,ActiveState,SubState,MainPID UNIT.service`` for the retained unit. Compare its invocation with the durable start-binding event; keep exclusive custody of the name while issuing ``systemctl stop UNIT.service``. Query again and use ``systemctl reset-failed UNIT.service`` only after the matching unit is inactive or failed with no live main process. A changed or missing invocation is unresolved and requires owner disposition, not a name-only stop. The query and stop are not atomic. Compare each remaining runtime path with its creation manifest before using ``unlink PATH`` on that one socket or FIFO; remove the empty case runtime directory with ``rmdir CASE-DIRECTORY``. A missing manifest, replacement object or publication partial is not permission to guess. Never remove completed outputs or evidence as runtime cleanup. Rerun only with fresh roots and a new policy.

Client signal scoping and binding the generator to the keeper's unit remain owner decisions; this program promises neither. The rehearsal must witness the keeper unit's ``KillMode=mixed`` and a ``TimeoutStopSec`` longer than the approved recovery allowance before a whole-unit stop is used. The operator procedure above signals only the keeper's main process and remains valid without those two pending mechanisms.

The generator start vector already sets ``TimeoutStartSec=case_ms``, ``TimeoutStopSec=5s``, ``SendSIGKILL=yes`` and ``KillMode=control-group``. A fixture stranded at its start barrier cannot retain a live process beyond the activation budget plus the manager’s five-second termination allowance; a failed unit record can remain and hold the reserved name. A manager stop sends SIGTERM then SIGCONT, and the barrier fixture retains SIGTERM’s default disposition, so it exits without emitting. Direct sealers install SIGKILL parent-death behavior before execution and refuse if their creating parent has already changed. This relies on the single-threaded keeper and does not bind the generator unit to it. A hard-killed keeper leaves no terminal lifecycle claim, and can leave runtime FIFO/socket names and publication partials; preserve these for reconciliation.
