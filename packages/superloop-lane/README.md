# The lane command

**Definition (Lane command)** · `def:superlooplane:lane-command` `superloop-lane` describes and starts the worker in one disposable home, builds its pinned image, and installs passive launch inputs; the durable driver commands share its dispatcher. The boxed launch's backend binding is the `backend_argv.codex` check in `launch.rs`, while the driver dispatches both backends through `driver start|resume --backend codex|claude`.

**Definition (Plan and launch stages)** · `def:superlooplane:plan-and-launch-stages` The plan is a launch contract for review and fixtures. `build` runs the container program on the calling owner's host and records the resulting image; `install` prepares a loop without activating it; `launch` creates the home and starts the driver, which supervises the container and saves evidence in the durable driver directory outside the home.

**Rule (Candidate plan measurements)** · `rule:superlooplane:candidate-plan-measurements` The plan records configured paths, mounts, and runtime options as candidates. Its measurement fields mark values that still need inspection on the launch host, including runtime-created mounts, image and socket inputs, template contents, and the worker UID allocation.

**Requirement (Launch model selection)** · `req:superlooplane:launch-model-selection` Launch selects model and reasoning effort from `Model:` and `Effort:` (or `Reasoning effort:`) in the letter's opening lines, then from `--model` and `--effort` for either missing field. A launch without both values refuses before reservation. The selected values and their sources enter the launch plan, reservation and protected launch evidence; the runtime vector passes them to Codex as `-m` and `-c model_reasoning_effort=…`.

**Protocol (Journal-bound resumed mail)** · `proto:superlooplane:resumed-letter-placement` The loop submits an ordinary letter through its own outbox to its worker. After service delivery, `bind-mail LOOP RUN --step STEP --delivery UTC_INSTANT` verifies the completed journal record, own-loop sender, selected worker, recipient inode and whole-file digest. The service pin becomes durable before the reservation gains its `mail` binding. `launch LOOP RUN --round STEP` re-verifies that same inbox delivery and requires ordinary resume authorization. Its prompt names `/mail/inbox/SENDER.DELIVERY.letter`; the driver retains the exact bytes as step evidence beside the brief before starting the resumed turn. A moved or changed inbox entry refuses rather than selecting another file. Model and effort remain those of the reservation. UTF-8 briefs retain the optional model, effort and cooperative-stop declaration convention; binary deliveries remain opaque and are preserved exactly. `send-letter` and `withdraw-letter` are retired commands; a delivered instruction is corrected by another delivery. Old `letters` reservations require cutover reconciliation.

**Protocol (Reply evidence)** · `proto:superlooplane:reply-mail-binding` A worker sends its reply through its outbox to its loop. `bind-reply LOOP RUN --step STEP --delivery UTC_INSTANT` verifies the inverse worker-to-loop delivery and retains its opaque bytes for settlement; it grants no steering or resume authority. Settlement compares the retained reply with the protected delivery binding, including the selected worker identity and digest. Both binding forms hold the reservation mailbox lock. Retirement releases the worker's service pin family only after custody transfer and configuration retirement. Journal compaction and pin publication share an admission lock; pruning re-reads the pin projection while holding it.

**Protocol (Seeded source handoff)** · `proto:superlooplane:seeded-source-handoff` `Sources: NAME [NAME...]` or `Sources: NAME@HEX [NAME@HEX...]` in the opening declarations names at most sixteen local Git bares, with HEX a full forty-character commit object ID; an unseeded bare is empty, while a seeded bare contains the named commit's reachable objects and only `refs/seeds/NAME`, fetched from the loop's private `src/NAME.git` before worker ownership, has `HEAD` pointing to the unborn `refs/heads/lane/RUN` branch, and the reservation records the seed, source identity and instant. For a seeded bare the worker runs `git clone "$HOME/.local/sources/NAME.git" NAME`, `git -C NAME fetch origin refs/seeds/NAME:refs/seeds/NAME`, then `git -C NAME switch -c "lane/RUN" refs/seeds/NAME`, and ships its committed `refs/heads/lane/RUN` with `git push "$HOME/.local/sources/NAME.git" refs/heads/lane/RUN:refs/heads/lane/RUN`; an absent or empty declaration creates none, and a worker-created bare is recorded as undeclared at checkpoint. Source movement follows (`[TOOLS-rule:buildcontracts:repository-boundaries]`).

**Protocol (Checkpoint preservation)** · `proto:superlooplane:checkpoint-preservation` `superloop-lane checkpoint LOOP RUN --dry-run` lists the settled run's retained legacy home slots with sizes and each bare's lane-ref state without writing a checkpoint. The changing form copies the inert legacy `.local/inbox` and `.local/outbox` slots and every `.local/sources` bare through held directory descriptors into the next `preserved/N` under the run's driver directory, makes the copy loop-owned, checks each copied file's size and SHA-256 digest, and checks each copied bare's ref against the source, with Git connectivity checks when a lane object exists. The owner-protected reservation records the checkpoint index, instant, settled round, file sizes and digests, and for each bare `lane_ref: absent` with a null object before the worker ships to it or `lane_ref: present` with its verified object after a shipped round; a later absence of a previously recorded ref refuses by name. Harvest skips an unborn bare when another bare shipped and refuses a checkpoint with no shipped bare. An incomplete copy remains in place with a refusal attempt recorded and no complete checkpoint claim. Source directories may carry setgid, which changes group inheritance without relaxing the checked ownership, owner access, or prohibition on group/other writes; exact pinned modes still apply apart from that bit. This is the lane's checkpoint implementation of (`[TOOLS-rule:workercontracts:letters-and-retention]`).

**Procedure (External checkpoint checkout)** · `alg:superlooplane:external-checkpoint-checkout` `superloop-lane checkout LOOP RUN --repo REPO --into DIR [--dry-run]` prepares an external clean checkout from the latest complete checkpoint's preserved `sources/REPO.git`. It refuses a missing or changed preservation, a nonempty or linked destination, and a destination beneath the owner's temporary home root or the runs root. The whole temporary home root is reserved for run homes, so an external checkout belongs elsewhere. Git transfers a pack between children bound to held source and destination directory descriptors, checks out `refs/heads/lane/RUN` as a local branch, sets the lane identity and disables signing, then verifies the object, clean status and directory inode. A token-bound pending record precedes creation; failure leaves the directory for the owner and records an attempt, including recovery after a private timeout. Successful checkouts are retained by source and checkpoint in a bounded list with an omission count. The dry run previews the source object and destination without writing.

**Rule (Import evidence retention)** · `rule:superlooplane:import-evidence-retention` `retention = "keep"` in `workers.toml` is the only supported retention policy and is the default when absent. `superloop-lane mark-imported LOOP RUN --object HEX` verifies the preserved checkpoint copy before recording which checkpoint and bare explain the import. A marked object's checkout tuple remains in the bounded checkout list and never contributes to `checkouts_omitted`; `retire` refuses `retire-import-evidence` while such a mark exists. The retention authority is (`[TOOLS-rule:workercontracts:letters-and-retention]`).

**Protocol (Harvest gate agreement)** · `proto:superlooplane:harvest-gate-agreement` `superloop-lane harvest LOOP RUN --gate-object HEX [--dry-run]` compares the latest complete checkpoint's preserved lane object with the server-reported checked-out object from the successful external gate, records their agreement under the mailbox lock, then checks every current inbox, outbox and source-bare file against the preserved sizes and digests before collecting the disposable home. The dry run previews the comparison and planned removals without writing. A mismatch, missing checkpoint, changed file or added source bare leaves the home; collection unlinks only beneath pinned home descriptors and records complete or interrupted disposition with observed remaining components. The run record and preservation remain under the runs root, and collection does not retire the run or release its worker UID. Collection applies (`[TOOLS-rule:workercontracts:letters-and-retention]`) through the recorded gate object and checkpoint.

**Precondition (Launch input checks)** · `pre:superlooplane:launch-input-checks` Launch checks mount roots, installed input hashes, the backend grant and local image identifier before container start, then saves its checks in the durable driver directory; the `make-home` stdout report and saved plan describe creation. Worker settings supply memory, process count and CPU shares; the registry supplies loop identity and runs root.

**Warning (Runtime environment trust)** · `warn:superlooplane:runtime-environment-trust` `runtime.env` is loop-group readable in a loop-owned run directory. Its recorded root identity lets an honest client reject a replaced runs root; the loop identity can replace this file, so it is not a boundary against that identity.

**Invariant (Run authority separation)** · `inv:superlooplane:run-authority-separation` The host session owner can reach the rootless image store, registry and loop settings; its namespace-owner helper checks one protected run reservation, accepts container requests from descendants of that run's launched driver session, and permits another attempt only after a bounded model-capacity error from the prior nonzero attempt. The helper checks the executable path through protected, link-free components again before each owner execution, so a loop-writable pathname cannot become its program. The loop-UID driver can write its durable driver directory but cannot change the owner-controlled worker-home root, installed runtime template, identity bind files, container identifier files, authoritative observation or helper sockets; the worker-owned home partitions are not writable by the driver. The worker uses its allocated UID inside the box and can write its planned writable mounts and runtime tmpfs; the owner-only sign-in directory is never mounted into a run. Session ancestry uses the recorded PID and process start tick without a pidfd, so a reuse of both values is not formally excluded. The worker and driver roles are defined by (`[TOOLS-rule:workercontracts:launch-and-evidence]`) and (`[TOOLS-rule:workercontracts:launch-and-evidence]`); external evidence is governed by (`[TOOLS-rule:workercontracts:launch-and-evidence]`).

## Commands · `sec:readme:commands`

**Definition (Request helper boundary)** · `def:superlooplane:request-helper-boundary` The five request commands `requests status|list|triage|review|adjudicate LOOP` call the separately released private `requests-helper` at its configured absolute path. Native builds set that path to `libexec/superloop/requests-helper` under the install prefix; `SUPERLOOP_LANE_REQUESTS_HELPER` selects an explicit replacement, without sibling-name or PATH lookup. `PERMISSION_TRIAGE_LOOP_REGISTRY` names the existing private loop registry. Permission judgements additionally require the helper's validated `PERMISSION_TRIAGE_REQUEST_CONTEXT`; the lane never grants permission authority itself.

**Procedure (Permission registry provisioning)** · `alg:superlooplane:permission-registry-provisioning` `requests provision-registry LOOP [--state-root DIR] [--dry-run]` derives the private permission entry from the protected estate registry row's name, session, launch directory, UID and loop home. It requires a registered session and refuses unsafe sources or destinations as `requests-registry-refusal`. The destination is `PERMISSION_TRIAGE_LOOP_REGISTRY`, or `~/.local/state/superloop/requests-registry` for provisioning; export that path for request readers and the door service. Permission state defaults to `~/.local/state/superloop/permission-state/LOOP`; select an existing journal with `--state-root DIR`. Both destinations must be normal paths beneath the calling home, separate from the loop home and authorization sources. The preview creates nothing. Apply creates private directories and an atomic mode-0600 entry, saves a `LOOP.provision.json` deploy report beside it, and leaves an identical entry unchanged on repetition. Existing nonprivate directories, linked paths and nonprivate entries refuse; the command does not repair their permissions or migrate journals. Deploy the private helper and its build-time binding before provisioning and verify `requests status LOOP` afterwards. The report also requires `direct_snapshot` and `direct_journal`, naming the registered policy file and separate direct journal. Apply republishes policy; the journal is never opened by provisioning. Run loop-home ensure for both tiers before provisioning. The deploy operator and the supervising loop read `LOOP.provision.json` as deployment evidence; `requests-helper` skips this non-`.env` file, although it counts toward the registry listing limits of 1,024 names and 65,536 bytes. The `changed` field excludes the report, which every successful apply rewrites, `changed=false` included. Reports include the pinned registry and state directory identities as `registry_identity` and `state_identity` (`st_dev`, `st_ino`), or null for an absent preview destination; `created_registry` and `created_state` describe actual creation, while `would_create_registry` and `would_create_state` describe absent preview destinations. Provisioning refuses destinations inside any estate loop home and state roots overlapping another private entry, using the helper’s deployment rules, which `superloop-lane` invokes through the private helper on its descriptor-pinned snapshot; deploy it and `requests-helper` from the same commit so both judge the registry by the same rules. A different existing `LOOP_STATE_ROOT` refuses by name; retain it with `--state-root` rather than silently selecting the default.

**Rule (Door request admission)** · `rule:superlooplane:door-request-admission` The door admits one active request per authenticated box across service and exercise processes, holds its per-loop, per-worker-UID admission lock through the final reply and effect and agent publication (in allow mode, agent publication can finish after the final reply), and polls a held guard every 100 milliseconds before creating any record, holding only the existing peer slot while waiting. The admission wait is capped at the smaller of 30 seconds and the request’s remaining deadline less a two-second reply margin; no remaining margin means immediate refusal on contention. A guard released within that wait admits the request normally. An exhausted wait refuses with reason `door-request-concurrent` and status 125, adds `waited_seconds` as the actual wait rounded to a millisecond and integer `retry_after_seconds: 30`, and retains `admission_window` as one sentence explaining the wait and retry advice. The worker’s stderr line keeps the reason prefix and prints `waited=` and `retry_after=` figures. Two boxes of one loop retain independent admission. Store locks cover custody transactions, including index maintenance and syncs, and are released before command execution or agent judgement. Door readers and writers retry contended acquisitions against the request's single absolute deadline; each writer acquisition also retains at least the base 15-second allowance from its start, including effects, deadline outcomes and agent publication recorded after that deadline, without repeating execution or changing the reservation. Non-compute store writers may wait up to the 120-second request deadline instead of 15 seconds. Compute store writers wait up to the compute request's own 1,800-second deadline because door writers retry against the request deadline (`proto:superlooplane:compute-deadline-and-evidence`). Other callers retain the default 15-second acquisition allowance. Each contended acquisition with a request ID logs a `door-request-lock` service-journal event with `wait_seconds`, read or write operation, outcome, request ID and `holder_request_id`; holder identity is known for a request writer in the same service process and null for other processes or shared readers. A sibling box in the same loop can see the holder request ID; this disclosure stays within that loop. Intermediate acquisition expiries use outcome `retry`, while the final expiry uses `timeout`. This is neither FIFO ordering nor a bound on kernel sync duration. A store lock not acquired within its applicable allowance fails as `requests-record-refusal`. Admission and recording replies retain the cause in `request_record_error`, including the lock, elapsed wait and known holder, and the worker's printed diagnostic includes it. A completed effect is retried on contention through the later of the request deadline and its base writer allowance before `door-record-incomplete`; non-contention failures are not retried. Preflight refusals retain their own reason and add `request_record_state: failed` with `request_record_error` when recording fails. Learned exact matches, mode floors and transitions, correction-pending audit, citation checks and setting evidence are supplied to execute-command as explicit observations. The door retains peer and route authentication, custody and existing reply rendering; an absent stored mode refuses as `door-mode-record-refusal`.

**Rule (Non-actionable preflight evidence)** · `rule:superlooplane:non-actionable-preflight-evidence` Both `status` and `list` retain non-actionable door preflight evidence in `preflight_refusals`. These original door records are not imported as pending common requests and cannot be reviewed or granted an effect.

**Warning (Compute admission gap)** · `warn:superlooplane:compute-admission-gap` The capability record's admission contract permits preflight refusals only for registration, identity, scope and transport failures, in every mode. Every other shape receives tier judgement: an exact learned match, the triage agent on a miss, and the loop's superloop for a loop-scoped referral. Adjudicated labels teach the fast lane within the registry floor. The measured command corpus is a learned-shape seed, not the boundary of registered authority. A superloop answering a door question reads (`[TOOLS-rule:workercontracts:capability-mediation]`), (`[TOOLS-rule:workercontracts:capability-mediation]`) and (`[TOOLS-rule:workercontracts:capability-mediation]`) first. The current closed compute grammar does not yet implement that contract: every compute command outside its admitted list and every compound recipe is still refused before judgement. Such refusals are implementation gaps, not evidence that an unseen shape is out of scope; expanding a command allowlist does not close the gap.

**Definition (Request and effect states)** · `def:superlooplane:request-and-effect-states` Request custody distinguishes an undecided intent (`state: null`, effect `pending`) from `waiting` for supervision, `marked` for review, and `adjudicated` with a request-bound label. `observed` records an outcome available for later judgement; `preflight-refused` is non-actionable admission evidence. Effect states `pending`, `completed` and `refused` are separate from those judgement states: an adjudicated allowance alone is not remote completion.

**Protocol (Common request adjudication)** · `proto:superlooplane:common-request-adjudication` `status` and `list [--pending]` read the common collection without creating its journal or a channel binding. A request's common identifier is 64 hexadecimal digits. `triage LOOP` accepts `{"schema":1,"items":[{"id":"IDENTIFIER","mark_for_review":true}]}` or items with `decision:{"answer":{"outcome":"allow"},"reason":"checked"}` for door requests. The helper validates every item before publishing any: unknown or duplicate identifiers, malformed answers and stale transitions refuse the whole batch. `review LOOP IDENTIFIER` refreshes only a marked request, returning its eight-digit `review.review_id` and UTC time. `adjudicate LOOP` reads `{"schema":1,"id":"IDENTIFIER","review_id":"REVIEW","decision":{"answer":{"outcome":"refuse"},"reason":"checked"}}` and requires the latest review. Permission request answers retain the permission package's schema and authority rules.

Request lookup identifiers are handles, while context and image verification require independently retained references under (`[TOOLS-rule:digests:full-digest-justification]`). The identifier and image formats described here remain reader contracts; display shortening cannot change them.

**Convention (Legacy request routing)** · `conv:superlooplane:legacy-request-routing` The legacy run-scoped triage array, colon-form door identifier, positional adjudication and `list --state` forms still enter this helper route. Review now requires an explicitly marked request in both forms. Mark an observed outcome before reviewing it. The common collection owns transitions and review history; door custody, modes, learned labels and effect evidence remain in this package. The first changing command records the exact helper and registry paths in the private `requests-channel.json` beside the loop configuration. Restarted readers use that binding. Publication validates a complete preimage and commits the common collection once; custody projections and learned-index maintenance follow it, and a failure there reports that the judgement has already committed. Readers overlay committed common records, including while rebuilding retained labels.

**Protocol (Single-use effect claims)** · `proto:superlooplane:single-use-effect-claims` A waiting before-effect request becomes service-pending after judgement. The door obtains a durable single-use claim before acting, then publishes its validated effect evidence through the helper. Repeated claims do not replay an effect. A departed waiter remains eligible for judgement but completes with a refusal and no performed effect; after-effect requests never start another effect. The collection also admits gateway proposals. The private gateway service owns their claims, execution and worker projections; the public `gateway` object dispatches administrative commands by configured exact path.

**Requirement (Resume plan agreement)** · `req:superlooplane:resume-plan-agreement` Resume compares the complete normalized current plan with the protected reservation before reconciling letters, in both the dry run and the changing form. A mismatch refuses with `plan-read` and the sorted differing keys, using the helper's comparison without additional reads. The helper still repeats its own admission checks before starting the box. The preserved launch contract is (`[TOOLS-rule:workercontracts:launch-and-evidence]`).

**Protocol (Door stub repinning)** · `proto:superlooplane:door-stub-repinning` For a settled run, or a started run in interrupted settlement (a completed driver end, no recovery settlement or last-round report), affected by an installed door stub change, preview `superloop-lane launch LOOP RUN --repin-door --dry-run`. Review the complete `before` and `after` door objects and `preview_sha256`, then apply `launch LOOP RUN --repin-door --expect-digest HEX`. This is a host-only form: it starts no worker and does not reconcile a round. Only `stub_sha256` may change; worker identity, socket and stub paths, registered extensions and mirror ref remain bound, and every non-door plan difference still refuses with `plan-read`. The digest binds the form, owner, loop, run, exact prior reservation bytes, both complete door objects, unchanged plan context, the transition's round boundary and its `boundary`, `settled` or `interrupted-settlement`. Apply recomputes the proposal and absence proof under the shared configuration guard, exclusive runs-root lock, existing preparation lease and mailbox lock. Missing locks, stale input, a live process or labelled container, and unknown presence refuse without changing the reservation. A deploy carrying a door binary is followed in every affected loop by re-pinning every resumable boxed run with a door before its next round: preview `launch LOOP RUN --repin-door --dry-run`, review both door objects and `preview_sha256`, apply `launch LOOP RUN --repin-door --expect-digest HEX`, then repeat the ordinary resume dry run. A run without a door refuses with `repin-door: this run has no door`.

**Register (Door pin history)** · `reg:superlooplane:door-pin-history` The explicit transition updates the recorded door and appends `door_pin_history`, retaining complete old and new pins, the bound digest, prior-record digest and the round boundary and its `boundary`: `settled` after a settled or failed last round, or `interrupted-settlement` for a started run whose last round an interrupted settlement left running or awaiting settlement; a row without `boundary` is a settled boundary. Both reservation readers validate present history; census and door-shape exercises expose it and the pin belonging to each recorded round. Retirement preserves this evidence. Earlier rounds keep their old pin in the report; a later resume starts a new box with the current installed stub, whose digest must match the new pin. A second installation requires a new preview and matching transition.

**Convention (Door repin compatibility)** · `conv:superlooplane:door-repin-compatibility` Compatibility: the lane command `superloop-lane` gains the listed re-pin form. Existing records keep their shape; only this explicit digest-bound form adds validated history and updates the door pin. Ordinary launch never backfills history or ignores a changed digest. The installer's generation shape is unchanged. No older same-run writer may run concurrently with a transition.

**Procedure (Installed input repair)** · `alg:superlooplane:installed-input-repair` `superloop-lane repair LOOP [--dry-run]` compares the local image ID, runner template and passive vendor unit with the loop settings, pinned build report and recorded unit directory, restores safe differences under the loop configuration lock and install generation record, and reports the planned boundary of a new run with its versioned mount entries, run-independent entry-set digest, limits, writable leaves and attested container options. A dry run reports the same proposed actions without changing installed inputs; a repeat changing run reports `changed=0`. An absent or mismatched pinned image, unsafe installed metadata or a generation without `unit_dir` refuses by name before repair writes; `install --pilot` records the unit directory after deployment and remains available after a template change. Repair does not enable or start units.

**Protocol (Door installation)** · `proto:superlooplane:door-installation` `superloop-lane install-door LOOP [--dry-run] [--podman-bin FILE]` checks the completed vendor generation and the pinned door programs, then records the private stub, service executable, socket directory and passive service unit under a separate completed door generation. That generation records the door directory's group as observed on the host after the namespace child sets it; the host compares the pinned stub and directory with that recorded group. A generation without the group refuses by name at install-door, launch and service; the reader accepts only the current shape. Protected run-record readers, including the exercise cases that only read a run, do not consult the current door generation; box probes and door cases do. A box-facing plan refuses a malformed generation whatever its roots; it refuses a missing generation, or one for other roots, when the service copy is present and the settings name the installed layout, the template at `.var/loops/LOOP/runner-templates/codex/HEX` under the owner home, where `sha256:HEX` is the image digest, and the sockets at `.var/loops/LOOP/sockets`; recorded door probes require a valid current generation. The host pins the template, its `libexec` and the socket directory beneath a verified owner-home descriptor and hands those directories to the namespace child, which compares the handed identities and checks and writes beneath their descriptors without walking from the namespace root. The child compares namespace root uid 0 and the row's group ID there; owner configuration checks and writes stay in the host view. The host's dry run after deployment verifies that namespace ownership mapping end to end. The changing run holds the loop configuration lock exclusively. The dry run first probes exclusive availability on a separate descriptor and reports `blocked: true` with holders when unavailable, then holds it shared through the read-only child; the child retains the handed mode. A changing run first records its attempt as `attempted` and marks it `complete` only after the generation is recorded, so an `attempted` record means a changing run began and did not finish; an older `attempted` record beside its matching completed generation is completed as one listed action. An unblocked dry run and changing run list the same actions and count when the observed inputs remain unchanged, and a repeat reports `changed=0` and writes nothing. A generation recorded for other template or socket roots is superseded: the service is replaced when it still matches either generation, the stub is placed in the new template and the new generation replaces the old one last. A conflicting destination refuses before any write, and installation does not start the service. A new plan binds the registered door directory read-only only when the generation names the plan's own roots and its stub and service digests still match, and a digest mismatch refuses; a missing generation or one for other roots gives a new run no door only outside the installed layout or before the service copy is present. The service links the registry's ledger reader, which refuses a key it does not know, so whenever the ledger shape changes the service deploys together with every other ledger reader and `install-door LOOP` records its new copy before the next start. The door abstraction is (`[TOOLS-rule:workercontracts:capability-mediation]`); this command records its installed implementation.

**Invariant (Door plan pin)** · `inv:superlooplane:door-plan-pin` The plan's door value contains seven keys: schema, socket path, stub path, stub digest, registered extensions, peer UID and mirror ref. The stub is a child of the host template's read-only directory bind, so replacing that directory entry would affect later executions in a live box; installation must retain the existing live-and-unknown exclusion. Resume creates a new box and uses the current installed stub. A service-only or agent-only door installation does not change this plan value when the stub bytes and bindings remain equal. A stub-changing installation requires the settled run's explicit re-pin before resuming; the helper never silently accepts a different stub digest.

**Rule (Door work scope)** · `rule:superlooplane:door-work-scope` The first `launch` can select `--door-scope work` for a work lane; the default is `review`. The protected reservation holds that scope across later rounds, and the door service uses the socket peer to select that reservation and its exact mirror ref. A review scope receives a typed compute refusal, and a request that names a mirror ref is refused. The `door-shape` case reaches a settled run through a `door-shape-probe RUN` request, which selects that run's reservation for the same peer without a live phase and receives only the typed reply.

**Rule (Request listing contention)** · `rule:superlooplane:requests-list-contention` `requests list LOOP`, including `--pending` and `--state`, shares one 15-second lock-acquisition deadline across its reads. A listing proceeds if the holder releases the lock within that allowance. On contention expiry it emits no listing, preserves the elapsed wait and known holder diagnostics, and tells the caller to retry the listing after the active request releases the lock. It does not extend the wait indefinitely or mutate request records. The deadline bounds lock waiting, not helper execution or filesystem reads.

**Protocol (Registered SSH transport)** · `proto:superlooplane:registered-ssh-transport` The service reads the owner-private compute route from the loop configuration directory: `door-compute-registration.json` records schema one, loop name, registered SSH alias, mirror root, the path of the registered `door-key` and the required absolute `node_root` from which compute derives its node environment, while `door-ssh_config` and `door-known_hosts` are protected derivatives of `door-node-registration.json`, verified against that registration before transport use. The checked configuration selects exact `Host` aliases or `*` with first-value precedence, retains SSH defaults for omitted connection fields and passes supported options directly to SSH with `-F none` instead of reopening its pathname; its guard refuses matching (`Match`), command, forwarding, session-control, identity or inclusion, and shared-connection directives, plus a quote or backslash anywhere in a non-comment line, with the directive named in each refusal. The lane neither creates nor reads the key. The service clears inherited environment and forces that registered identity, no agent and no shared SSH connection. The optional `git_upload_output_limit_bytes` is a positive integer from 1 through 1,073,741,824; absence selects 16,777,216 bytes, a value in that same domain. It bounds combined stdout and stderr for both Git upload variants. The loop's door host step writes its reviewed ceiling before enabling large uploads; for example 536,870,912 gives a 512 MiB budget. The service announces the selected ceiling before streaming output and the stub enforces it without buffering packs. A larger ceiling takes effect per loop at its next template install carrying the new stub; an older stub retains its own 16 MiB ceiling. Git requests retain their 120-second deadline. Receive accepts `shallow HEX` declarations only before update commands, with exactly 40 or 64 hexadecimal digits and a terminal LF; it validates the whole declaration, keeps every update restricted to the registered ref, and holds the guarded prefix (at most 64 KiB) until the flush. A shallow-only flush is `no-ref`, never `admitted`. A rejected command-section packet adds `ref_packet` evidence: `word_count` (0 through 65,536) and `first_word` (at most 64 printable ASCII bytes, with `[non-text]` or `[overlong]` replacing unsafe or oversized words). No bytes after the flush enter that evidence. On-disk mirror bytes are not a wire-size bound because stored deltas may expand when their base is omitted. An exact Git upload option for `SendEnv=GIT_PROTOCOL` selects protocol version two; an upload without it leaves that variable absent. The stub streams stdin, stdout and stderr over the registered socket, returns the transport status and records the compute exit status separately; the final frame reports the request wait, mediation and compute walls and the ref-check outcome. The changing generations form moves only the templates under loop configuration locks, never removes an image tag or image data, and reports `changed` only when a template moved.

**Protocol (Node retirement handoff)** · `proto:superlooplane:node-retirement-handoff` Run retirement also retires the node workspace when the loop has a compute registration. It records node work as owed before the host custody moves, then contacts the node only after the retired reservation has been renamed and the runs directory synced. The owner-side bridge uses the door's protected registration loader and SSH construction, with the registered alias, mirror root, node root and key pathname; it does not call the door socket or open the key. Under the loop's node account, the embedded helper takes the run lock, durably publishes the marker, measures the four paths (`RUN` and `RUN.lock` beside the mirror root, `RUN-build` and `RUN-tmp` in the node root's `lanes`), removes `RUN`, `RUN-build`, `RUN-tmp`, then `RUN.lock` last, and measures them again. The host preparation lease is distinct and remains in place.

**Register (Node retirement measurements)** · `reg:superlooplane:node-retirement-measurements` `node_retirement` retains the plan, current outcome and up to four prior outcomes, with an omitted count. Measured outcomes contain the helper's schema-one `NODE-RETIREMENT` evidence: before/after existence, entry counts and bytes for all four paths, bytes freed, helper wall and exit, and marker publication. The before listing is taken after acquiring the run lock, which creates `RUN.lock` if absent; that row therefore includes the helper’s own lock even for a run that never computed. Entry counts include the named root; traversal does not follow symlinks. Bytes are allocated blocks times 512, with each hard-linked inode counted once across the listing. Bytes freed is the nonnegative difference of the totals: a path-accounting delta, not a filesystem free-space guarantee. Host wall and transport exit, when available, remain distinct from the helper's measurements.

**Rule (Node retirement failure policy)** · `rule:superlooplane:node-retirement-failure-policy` Each host attempt has a 120-second bound covering connection, lock waiting, measurement, removal and evidence. Retirement SSH alone uses `ConnectTimeout=10`; the door’s other SSH commands are unchanged. The node independently runs the helper under `timeout -k 5 105`, leaving margin within the host bound, and the host bounds and reaps its SSH process group. Lost or invalid final evidence, an unreachable node, missing tools, deadline or removal failure leaves a typed outcome with `owed: true`; it does not reverse host retirement or retain the worker UID. If no compute registration exists, the outcome is `unmeasured`, reason `node-retirement-no-registration`, and not owed. A malformed registration is owed and names `node-retirement-registration-refusal`. A local timeout without helper evidence records unknown remote completion, never success. A partial removal retains the marker and available measurements for an idempotent retry.

**Protocol (Node retirement completion)** · `proto:superlooplane:node-retirement-completion` Use `superloop-lane retire LOOP RUN --node --dry-run` to inspect outstanding node work from the archived record, then `superloop-lane retire LOOP RUN --node --expect-digest HEX` to finish it. This form changes only `node_retirement`, retaining its bounded outcome history, and never repeats host custody moves or releases a UID again; four already-absent node paths are a measured success, while an outcome with `owed: false` refuses as `retire-node-not-owed` without SSH. An invalid or absent registration refuses owed debt as `retire-node-registration` before changing the record, carrying the registration's own refusal text or `node-retirement-no-registration`. It refuses a current reservation of the same name (`retire-node-active-run`), several matching archives (`retire-node-ambiguous`), or a changed recorded route, including the protected SSH configuration digest (`retire-node-route`). If the route changes during interrupted host retirement, custody still completes and the original destination remains owed as `node-retirement-route-changed`, without contacting either node. To finish that debt, restore the recorded alias, mirror root, key path and protected SSH configuration contents, then repeat the node preview and completion. Do not repoint the debt to a replacement node: it cannot remove the original node’s paths. An archive without `node_retirement` reads as "retired before node retirement existed" and retains explicit completion using the current registration; without a registration it refuses as `retire-node-not-owed`. Census exposes this interpretation and current debt; malformed present evidence refuses in the shared reservation reader, census and completion reader.

**Precondition (Retirement preview digest)** · `pre:superlooplane:retirement-preview-digest` Both run dry-run forms print `preview_sha256` and the node plan: alias, paths relative to the node account's home, marker, helper digest, deadline and failure policy. They make no SSH call except the bounded read-only absence probe for a run missing process identity; that probe runs under the runs-root, preparation-lease, mailbox and request-store guards, and apply remeasures it before recording settlement. A mismatch refuses `retire-digest` before custody changes or node cleanup; the missing-identity route also checks it before publishing its measured reconciliation. The digest excludes elapsed times but binds the measured absence proof, including node processes and lock state; other previews do not attest a node listing. Republishing a reservation can change its inode and planned retirement target, requiring a fresh preview even if its JSON contents are restored. The generations form is unchanged.

**Procedure (Run census and admission)** · `alg:superlooplane:run-census-and-admission` `superloop-lane census LOOP` reads protected reservations and retired reservation records beneath the owner-controlled runs root, reports their phases, recorded process identities and PID/start-tick presence, and attributes journaled path names to the record that planned them without entering loop-owned driver directories or worker homes. Launch recovery records its first completed move in `dead_preparation_retired` and later moves in `retry_retirements`; `retire` records its move in `current_retirement`. Attribution follows each journal's recorded target, including older name forms, and marks a name claimed by more than one record as ambiguous. The preparation lease `.prepare-RUN.lock` stays at its stable name by design after retirement and is attributed to the retired record when its name occurs in the runs-root enumeration; a lease without a reservation or retired record remains a skipped name, as do other unknown root entries. Census also reports the allocation range and launch admission state. Each row's `credential_refresh` includes `expires_unix` and `refresh_due_unix`, with null for unavailable or invalid values. Its state is `measured`, `absent`, `invalid` or `unmeasured`; `reason` distinguishes a missing file, a missing field, invalid fields, a disagreeing due instant and a helper check that could not measure the instants. `evidence_state` preserves the helper's state and `refused` its refusal kind. A refused token request can retain measured instants. Temporal defects affect only that row, so the rest of the census remains available. Retired rows are unmeasured with reason `retired` and null instants, including when a new reservation reuses their run name. The two recognized historical helper envelopes produce an `unmeasured` credential row with null instants and reason `historical-envelope:four-key-run-refusals` or `historical-envelope:five-key-refusal`. For those rows, `superloop-lane census rewrite LOOP RUN --dry-run` previews optional conversion, subject to the rewrite's reservation and absence checks. Historical evidence does not prevent other census rows from being reported. Unknown or corrupt envelopes, malformed JSON, unsafe custody, unreadable evidence and oversized evidence still refuse the whole census with status 2; those refusals do not recommend rewrite. `superloop-lane pause LOOP` records a paused admission and its Unix wall time under the exclusive loop configuration lock; a public launch holds the shared lock and refuses `launch-paused` while paused. `superloop-lane resume LOOP` records the return to running admission and its wall time. A live credential helper continues publishing while admission is paused, and retirement remains available.
